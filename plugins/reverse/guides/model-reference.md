# Modelling and scan reverse engineering — reference

The shapes behind the model and scan-to-cad guides. Every tool is the page's command with dots turned into underscores (`reverse.feature.add` is `reverse_feature_add`); the Reverse engineer's own begin with reverse and an underscore. Inputs are JSON; lengths in mm, angles in degrees unless a field says radians. A field marked `?` is optional.

**How answers come back.** A tool answers JSON; numbers are kept to six significant digits, except the exact answers — `reverse_feature_list` and `reverse_plane_describe` — whose numbers are meant to be handed back as inputs (a batch holding one keeps every answer exact). A refusal comes back as text `code: message`, marked as an error; in a batch, as `{ tool, ok: false, error: { code, message } }` (see Errors).

**Every tool that changes the session** is one undo step, takes `wait?` (see `scanruler_wait`), and runs as a job the server keeps. A Reverse engineer change that built anything also answers `steps: { recomputed, restored }` — steps its builds played, and steps taken up from a state the kernel held (a parameter set back, the rollback bar moved: none played). In a batch with `timings: true` it adds `steps.played: [{ feature, ms }]`.

## Command shapes

### The server's own tools

**`scanruler_status`** `{}` — `backend` ("page" or "headless"), `connected`, `page: { app, version, origin, plugins, viewport, hidden, commands }`, `server` (`server.role`: `holder` — this copy holds the tab's connection; `relay` — another copy, another chat or AI app, holds it and this one sends its calls through it, `server.holder.version` saying which; `none` — neither yet, `server.error` saying why; the work runs in the tab either way), and when it applies `howToConnect`, `hiddenNote` (the tab is hidden: keep the site active in Chrome's Memory Saver), `jobs: [{ job, tool, state: "running" | "done" | "failed", ms | runningMs }]`, the running ones and the newest 5, `jobsMore` counting the rest — or `jobsNote` when this server copy has none (it started at that time; changes asked of an earlier copy are not known here). `tools: { stale: true, added?, removed?, changed?, listedFrom, note }` (the names once, counts after) when the tools this chat was given are not the ones the page offers now (model guide §1). `folders`: where a scan or project was opened from or saved into, latest first, kept across a restart. `lastProject`: the `.scanruler` last opened or saved here. `page.stale` (with `staleNote`) after a `stale_page` (Errors). `server.answerWithin`: the seconds a call is held before it answers `{ queued: true, job, after }` (45 by default; `--answer-within`). `session: { scan, project?, unsaved, … }` says what the page holds — the scan, the project's name, whether it has changes not saved, and its work counted (features, notes, elements): another part on the page is seen here before anything is opened over it.
Example: `{}`

**`scanruler_write`** `{ path, text }` — page mode: `.md`, `.txt`, `.csv` or `.json` (UTF-8), only in or below a folder a scan or project was opened from or saved into (`saveTo`); a bare name goes beside the scan. Refused before a `scan_open` by path, in hidden folders and for agent or tool files (`CLAUDE.md`, `package.json`…).
Example: `{ path: "sigma_REPORT.md", text: "# …" }`

**`scanruler_files`** `{ path? }` — the files in the scan's folder or under it: name, size, kind (mesh, project, step, picture, drawing, text, other), newest first. Refused before a scan or project is opened from a folder.
Example: `{}`

**`scanruler_open`** `{}` — opens ScanRuler in the user's browser, paired, and waits for it; answers the status with `opened`. Headless: there is no page to open.
Example: `{}`

**`scanruler_wait`** `{ for?: "page" | "idle" | "job", job?, timeoutSeconds? }` — page (the default): until a page is connected; idle: until it is also not busy and every queued change has finished, answering `{ connected, state, finished }`, `finished: [{ job, tool, state, ms, error? | failed? }]` — each change done or failed since the last such answer, once; job: until that job is done, answering `{ job, tool, state, ms, result }` or `{ …, error: { code, message } }` — `state: "running"` if the time ran out first: call it again. 120 s by default, 600 at most, never past the server's answer limit (45 s). A job of an earlier server copy is read from the page's record (`session_recent`), `from` saying so.
Example: `{ for: "job", job: "j14-3f2a" }`

**`scanruler_batch`** `{ calls: [{ tool, arguments? }] | file, stopOnError?, rollback?, build?: "each" | "end", timings?, wait? }` — up to 200 calls in order, each the tool's own arguments (a `wait` inside a call is ignored; the server's own tools cannot be batched). `file`: a JSON file of the calls (`[{ tool, arguments }]`, or `[{ name, input }]`, as a list or under `calls`/`steps`), relative to the server's folder — a long run a script wrote. `{ "$file": path }` anywhere in any tool's arguments is that file's JSON. Answers `{ results: [{ tool, ok, result } | { tool, ok: false, error }], ran, of }`, and when it stopped `stopped` (the index) and `failed: { index, tool, error }`. A refused **change**, with `rollback` (default true) and `stopOnError` (default true), undoes every change the batch made before it — `undone` lists the step labels taken back, newest first (`rollbackError` if that undo itself failed); `rollback: false` keeps them. A refused **read** undoes nothing (`kept`). A call refused `busy` is run again once the page is idle (`retried: "busy"`). `stopOnError: false` runs every call and reports each, with no rollback. `build: "end"`: a run of model changes builds once, at the last call (the others answer `build: "held"`, the part as last built — an index pick names a face of that part); a read of the part met on the way builds first. `timings: true` adds each result's `ms`, the batch's total_ms, and on a change `result.steps.played`. `wait: false` answers `{ queued: true, job }` at once, as does a batch still running at the answer limit. A picture in a batch is never shown: it goes to its call's `path`, or to a numbered file in `scanruler-work` inside the open scan's folder (answers too long to carry go there too — not the person's deliverables), and the result's `file.path` says where.
Example: `{ calls: [{ tool: "reverse_feature_add", arguments: { feature: { kind: "sketch", name: "Boss", plane: { kind: "world", axis: "z", offset: 8 }, sketch: { entities: [{ id: 1, kind: "circle", c: [20, 0], r: 6 }] } }, detail: "none" } }, { tool: "reverse_feature_add", arguments: { feature: { kind: "extrude", sketchId: "Boss", extent: { kind: "distance", from: -0.5, to: 6 } }, detail: "none" } }], timings: true }`

### Session, history, files

**`session_state`** `{}` — the whole session: app and plugins, workspace, `busy`, the scan, elements, dimensions, sections, deviation, the undo history, and the Reverse engineer under `plugins.reverse` (kernel, build, parameters, feature rows, rollback bar, bodies, and `notes: { open, answered, waiting, fromFile, done }` while there are any). While a command runs, `running` names it with `runningSince` and `runningMs`. Read-only; answers while a change runs.
Example: `{}`

**`session_recent`** `{ job?, limit? }` — what the commands an agent's server ran as jobs became, newest first (the page keeps the last 100): job, command, state, ms, result or error. Read-only.
Example: `{ job: "j14-3f2a" }`

**`scan_open`** `{ path, name?, units?: "mm" | "cm" | "m" | "in", discard?, saveTo?, wait? }` — opens an STL, PLY, OBJ or 3MF as the scan (a folder: the one mesh in it, or a list of them); refused while work stands (the refusal names it: features, notes, elements, the project and whether it is saved) unless `discard: true`. `saveTo` (a `.scanruler` path) saves the session there first and then opens — one call, nothing lost; `savedTo` in the answer. A reference part opened from a file stays (`referenceKept`); one the Reverse engineer made from its bodies goes (`referenceDropped`). Not undoable. `project_load` and `session_reset` take `saveTo` too.
Example: `{ path: "C:/parts/bracket.stl", saveTo: "C:/parts/backup_before-bracket.scanruler" }`

**`project_save`** `{ path? }` — the session as a .scanruler project (scan, measurements, the feature list).
Example: `{ path: "C:/parts/bracket_CAD.scanruler" }`

**`project_rename`** `{ name }` — names the saves, the exports, the tab and its restore points.

**`history_checkpoint`** `{}` — marks where the undo history stands; answers `{ checkpoint, top, steps }`.

**`history_restore`** `{ checkpoint, detail?, wait? }` — undoes every step since that mark, newest first; answers `{ undone, after }`. Refused if the mark is gone.

**`history_undo`** `{ detail? }` — the last step back; answers `after`, in brief (`detail: "full"`: `state`, the session).

### Scan and measuring

**`scan_nearest`** `{ at: { point: [x, y, z] } | { vertex } }` — the vertex, its coordinates, outward normal, a triangle, the distance from the point.
Example: `{ at: { point: [12, -4, 30] } }`

**`scan_query`** `{ box: { min, max } | near: { at, radius }, normal?: { dir, withinDeg? }, limit?, fields?: "count" | "ids" | "all", mark? }` — vertices in a box or ball, optionally facing a way (30° by default), at most `limit` (1000; 20000 max, evenly thinned). Answers `matched`, `step`, box, centroid, mean normal, and with `fields` "ids" the vertex numbers, "all" (the default without `mark`) points and normals too; "count" (the default with `mark`) leaves them out. `mark: true` marks every matched vertex, not only those answered, for `element_fit_marked { marked: true }` or a surface's `region: { marked: true }` — no list through the context.
Example: `{ box: { min: [0, -20, 9], max: [40, 20, 11] }, normal: { dir: [0, 0, 1] }, limit: 5000 }`

**`scan_draft`** `{ pull: [x, y, z], box?: { min, max }, nearDeg?, patches?, minArea? }` — the scan's walls within `nearDeg` (10) of running along the pull, as patches, largest first: `draftDeg` (positive lets go along the pull, negative is a back draft), `sigmaDeg`, `spreadDeg`, area, count, centroid, box, `facing` (which way the wall faces across the pull). `split?: plane | "XY" | "YZ" | "XZ" | "symmetry"` keeps patches to one side of it (`side` on each). Patches join points facing within 20° of the patch's mean, so a smooth freeform wall comes in patches that turn 40° at most (`turnDeg`): a box's four sides are four patches, a thin wall's two sides (a blade, a rib) two patches facing apart, a boss's or hole's round side one with `round: true`. Read-only.
Example: `{ pull: [1, 0, 0] }` — a side core along X

**`scan_fit_surface`** `{ vertices | box: { min, max }, normal?: { dir, withinDeg? }, model?: "plane" | "bilinear" | "quadric" | "best", limit? }` — the patch's frame (origin, basisU, basisV, normal: its best plane) and per model `coefficients` of the height over (u, v), `rms`, `worst`; the quadric's `curvature: { k1, k2, r1, r2, axis1, axis2, shape }`; `best` (the default asks for every model) names the simplest within a tenth of the lowest rms.
Example: `{ box: { min: [10, -5, 2], max: [30, 5, 14] }, normal: { dir: [1, 0, 1] } }`

**`scan_qa`** `{ axis?: "x" | "y" | "z" | [x, y, z] }` — before modelling, in one call: open rims (count, total length, the longest with their number `rim`, centre and size; a rim on a circle has `circle: { center, axis, radius, rms }`, and `circles` lists more — holes the scanner did not see into, made elements by `element_fit { kind: "circle", rim }`), noise (median and p90 scatter of small plane fits — σ_scan), and thickness through the part along the axis (given; the alignment's z; else the way most of the surface faces): p5/p50/p95, and on the cells at the usual thickness `tiltDeg` — how far faces that should be parallel are apart — with `thickensToward`, `run`, `over` and each face's own tilt (`faces: { topDeg, bottomDeg }`); `notes` on what looks wrong. Read-only.
Example: `{}` — or `{ axis: "z" }`

**`scan_heightmap`** `{ box: { min, max }, axis?: "-z" | "+z" | "-x" | "+x" | "-y" | "+y", cell?, picture?, path?, inline? }` — the first scan surface met looking along `axis` (`-z`, the default: down from above, the top's heights; `+z`: up from below — ceilings, pocket roofs, the underside) over a grid in the box: `grid` rows of the coordinate along the axis (0.01 mm; null where nothing is hit), `origin`, `cell`, `cols`, `rows`, `min`, `max`, `hit`; at most 1600 cells. `picture: true` adds the grid coloured by height with a scale. Floors, ceilings, ledges and cell heights in one call.
- **`plane`** in place of `axis` maps square onto any plane. It takes a plane element (id or name), "XY" / "YZ" / "XZ", or `{ origin, normal, u? }` for a face or a Reverse engineer plane (from `reverse_plane_describe` or `reverse_body_describe`). Cells lie in the plane's own u and v, as a sketch on it has them, and heights run along its normal. A fitted plane looks at the side its scan is on; `flip` turns it. `box` is then `{ min: [u, v, h], max: [u, v, h] }` in that frame, the whole scan by default. The answer's `plane: { origin, u, v, normal }` gives a cell's world point: origin + u·U + v·V + h·normal.
- **`of`**: `"height"` (the default); `"deviation"` (the current map at each hit, null where unmeasured); `"relief"` (the height less a plane fitted to the cells around it within `smooth` mm, so icons, grooves and lettering stand out of a leaning or curved face).
- **`levels: true`** answers the heights clustered into levels instead of the grid: `{ height, sigma, range, area, sharePct, box }`, largest first, with `gap` and `noise`. A button's tiers, a pocket's floor, a plateau. Of a height, cells steeper than `slopeDeg` (10° by default; 90 keeps all) are left out first and counted as `sloped` — a fillet's ramp no longer joins two tiers; a face leaning more is mapped square onto it (`plane`).
- **`grid: false`** gives the picture alone, up to 160 cells a side.
Example: `{ box: { min: [-20, -20, -1], max: [20, 20, 12] }, axis: "+z", cell: 1 }` — or `{ plane: "Corner face", of: "height", levels: true }` — or `{ plane: { origin: [22, -14, 12], normal: [0.5, -0.7, 0.5] }, of: "relief", smooth: 1.5, grid: false, picture: true, path: "…/button_relief_04.png" }`

**`scan_outline`** `{ axis? | plane?, flip?, box?, tolerance? (0.2), loops? (4) }` — the scan's outline seen along an axis or square onto a plane (as `scan_heightmap` takes them), read as a sketch draws it: per loop, largest first, `hole`, `area`, `box`, `points` ([u, v] corners), `rounds` (corner rounds: `at` the corner's index, radius, center), `arcs` (sides of their own: `from`, radius, center), or one `circle { center, radius, rms }`, and `worst` (with `worstAt` past the tolerance). A flange's plan, a bezel's opening. Read-only.
Example: `{ axis: "-z", tolerance: 0.1 }`

**`scan_pattern`** `{ axis, at?: [mm, …], radius?: { min?, max? }, maxCount? (60), instances? }` — rotational repeats counted from the scan, cut square to `axis` (an element, "X"/"Y"/"Z", or `{ origin, dir }`) at each height in `at` (6 spread over the scan by default, 12 at most): `count`, `pitchDeg`, `phaseDeg` (the first copy's middle) and `betweenDeg` (midway to the next) — angles as `section_cut { across: { axis, angleDeg } }` takes them — `score` (under 0.5: no repeat, count 1; `tried` gives the best), per copy in `instances` its angleDeg, radius, `offDeg`, `rms`, `worst` and `share`; `rings` — round outlines about the axis, each radius, `off` and `towardDeg` from it. Give `radius` round one feature where several share a height: the one with most outline sets the count. Read-only.
Example: `{ axis: "Bore", at: [4, 9], radius: { min: 20, max: 48 } }`

**`scan_segment`** `{ kind?: "plane", box?: { min, max }, minArea?, maxRms? (0.05), maxDeg? (15), limit? (20, ≤ 200), symmetric?: plane | "XY" | "YZ" | "XZ", mark?: id | [id, …], list? }` — the scan's flat faces in one call, grown from the flattest points, each vertex in one region at most. Each region: `id` (largest first), `normal`, `point`, `sigma`, `area`, `box`, `count`, `curved: { sagitta }` (a strip of a curved surface, not a face), `run`, `neighbours: [{ id, deg, smooth }]` (`smooth: false` a crease; within 35° listed past `limit`). Top level `maxRms`, `noise`, `curvedRuns: [{ regions, along?, cylinder?, note }]` — one surface each, the `note` saying how to model it; read them before taking regions for faces. `symmetric` pairs mirror twins (`mirror: { id | "self", deg, mm }`). Small facets rank low on a large part: give a `box` round one band, or a higher `limit` — on the last housing both flanks ranked below 70th. `mark: id` (or several, their union), with the same options, marks the region's points for `element_fit_marked { marked: true }` and answers `{ found, marked, region }` alone (`list: true` adds the list). Read-only; about 1.5 s and 15 kB on 1 M vertices.
Example: `{ box: { min: [-30, 0, 0], max: [30, 40, 22] }, limit: 40, symmetric: "XZ" }` — then `{ …same, mark: 7 }`

**`element_fit`** `{ kind: "plane" | "sphere" | "cylinder" | "cone" | "torus" | "point" | "circle", at: place | [place, …], sigma?: 3 | 2 | 1 | 0, side?: "inside" | "outside", radius?: { min?, max? }, axis?: [x, y, z], within?: { min, max }, assumed?, orient?: { to, relation? }, extend?, name?, wait? }` — a place is `{ point: [x, y, z] }` or `{ vertex }`; aim at the feature's middle. A seed snaps to the nearest scan vertex and grows over what fits: near a rim it can take the wrong surface (a cup's underside for its inside). Steer it: `side` (sphere, cylinder, cone) — the concave inside of a bore or cup, or the convex outside of a boss or ball; `radius` — the size range meant; `axis` — a cylinder's or cone's direction, so a seed at a hole's centre finds its wall; `within` — the region stays in the box. A fit that finds nothing as asked is refused naming the radii it saw — and one turned down for its axis names that axis, a point on it, how far off it lay and its points: give it as `axis`, or drop `axis`. `kind: "circle", rim: n` in place of `at`: a circle through `scan_qa`'s rim n, answering `rim { index, points, rms }`. Answers the element, its fit (radius, form error, coverage, points), the seed used and the `region` it grew over (`area`, `box`; a plane's `normalSpreadDeg`). A plane whose region covers two surfaces answers `warning: "two surfaces? …"` with `region.second` (share, centroid, box, angle, offset) — shrink `within` away from it or move the seed; don't keep the plane. Several places in `at`: each seed answers `inRegion`, `offMm`, `deg`, and one on another surface warns — fit each alone. A cylinder does the same (`region.second`: share, band along the axis, axis angle, both radii, each part's normal lean) — a tilted lip over a vertical wall is two surfaces: fit each, or the cylinder ∩ a wall limiter. A torus takes a spine up to 5 × the scan's diagonal (a long, gently bent tube); past that the refusal says so. `mark: true` leaves the region's points marked.
Example: `{ kind: "cylinder", at: { point: [20, 0, 5] }, sigma: 2 }` — or `{ kind: "sphere", at: { point: [0, 0, 6] }, side: "inside", radius: { max: 8 } }`

**`element_fit_marked`** `{ kind, vertices: [n, …] | marked: true | box: { min, max }, normal?: { dir, withinDeg? }, sigma?, assumed?, orient?, extend?, name?, wait? }` — fits exactly those vertices; with `marked: true` the points `scan_query { mark: true }`, `scan_segment { mark }` or `element_fit { mark: true }` left marked; with `box` (and `normal`, 30° by default) every vertex in it, answering how many — no list sent.
Example: `{ kind: "plane", box: { min: [10, -5, 8], max: [30, 5, 12] }, normal: { dir: [0, 0, 1] } }`

**`element_construct`** `{ kind, method, refs?, params?, seed?, vertices?, assumed?, orient?, name?, wait? }` — methods: point-coords, point-centroid, point-midpoint, point-line-plane; line-two-points, line-axis, line-plane-plane; plane-three-points, plane-offset, plane-midplane, plane-coords (`params: { nx, ny, nz, px, py, pz }`), plane-symmetry (`seed: "XY" | "YZ" | "XZ"` or a plane; answers `symmetry: { rms, matched, sampled }`); circle-plane-cylinder, circle-plane-sphere, circle-coords.
Example: `{ kind: "plane", method: "plane-coords", params: { nx: 0, ny: 0.4226, nz: 0.9063, px: 0, py: 0, pz: 12 }, name: "Roof" }`

**`align_auto`** `{ level?: "settled" | "largest", detail?: "brief" | "full", wait? }` — a coarse pose read off the scan; `square` gives each axis's faces with their residual tilt (a drafted wall leans by its draft), `level: "largest"` squares the largest face exactly.
Example: `{}`

**`align_datum`** `{ primary: { element } | { points: [3 points] }, primaryAxis?, secondary?: { element } | { points: [2 points] }, secondaryAxis?, origin?: { element } | { point }, detail?, wait? }` — axes as "x+", "z-" …; primary default z-, secondary default x+. An origin alone shifts without turning. A plane as `secondary` puts its outward **normal** on `secondaryAxis`; points — the origin's too — are used as given, not snapped to the scan (`scan_nearest` first). **The origin sets only the coordinates the datums leave open**: with a plane and a line, only the one along the line. The answer's `origin: { set, at }` says which, with a note when the origin point stands off zero along the others — then call again with `origin` alone. A first alignment centres the coordinates nothing sets on the scan's box (`centred: ["y"]`); `keepFree: true` leaves them. `parallelFace` (offset, area times, note): a face parallel to the levelling plane within 5 mm holds more of the scan — the part may stand on that one.
Example: `{ primary: { element: "Base" }, secondary: { element: "Hole axis line" }, origin: { element: "Hole 1" } }`

**`align_symmetry`** `{ detail?, wait? }` — re-poses the part on its mirror plane; refused when there is none.
Example: `{}`

**`section_cut`** `{ across: element | "XY" | "YZ" | "XZ" | { axis, angleDeg }, offset?, name?, wait? }` — keeps a section of the scan. `{ axis, angleDeg }`: a plane through an axis (a cylinder, cone, line or circle element by id or name, or "X"/"Y"/"Z"), turned about it — a half section, u out from the axis, v up it (toward the + end of the nearest coordinate axis), never mirrored; 0° is the next coordinate axis round (X about Z), right-handed. `name` it, and later calls take the name.
Example: `{ across: "XY", offset: 6.5 }` — or `{ across: { axis: "Bore", angleDeg: 12.86 }, name: "Between blades" }`

**`section_get`** `{ section, chains?, space?: "sheet" | "world" | "both", limit?, skin?: "outer" | "inner", facing?: { dir: [u, v], withinDeg? (60) } }` — the cut's polylines, [u, v] on the section plane, and the plane (origin, normal, basisU, basisV). `skin` keeps one skin of a thin wall (outer: facing away from the cut's middle; inner: the wall's other side; ribs and bosses neither), `facing` the points whose way out lies near `dir`; each chain then comes back as its runs (`run`).
Example: `{ section: 2, space: "sheet", limit: 2000 }`

**`section_render`** `{ section | plane: { origin, normal } | element | { sketch }, offsets?: [mm, …], up?: "x" | "y" | "z", frame?: { at: [u, v] | [x, y, z], size } | { world: { min, max } }, tolerance?, layers?, width?, height?, path?, inline? }` — `plane` as an element (id or name) is cut in the frame a sketch on it gets, `{ sketch: id | name }` in that sketch's own; a PNG of the section: the scan's cut as points, grid in mm on round world values — labelled in world coordinates where u or v runs along a world axis, the world direction across and up named in the margins (`axes` in the answer) — scale bar, the bodies' cut (layer `bodies`; a sheet's as an open line of its own colour) and every sketch lying in that plane (whatever it was drawn on) with its pieces' ids; `up` turns the sheet so that axis runs up (`up: "z"` on a side plane: a CAD front view) — then `frame` and every [u, v] are on the turned sheet the answer gives as `sheet`, not a sketch's (every answer gives `sheet`; a frame in world is put on it for you); points off the outlines by more than `tolerance` (the Deviation workspace's by default) red. Answers `gap: { points, read, over, outside, inside, max, rms, overBox }`, `layers`, `map`. `offsets` (2–9): that many cuts parallel to it, mm along its normal, side by side in one picture on one frame and scale, each tile titled with its offset — the outline at several heights in one look; answers `tiles: [{ offset, origin, gap }]` and `sheet.origin`.
Example: `{ section: 3, frame: { at: [18, 12], size: 8 } }` — or `{ plane: { origin: [0, 0, 0], normal: [0, 0, 1] }, offsets: [1, 2.5, 4, 6, 8] }`

**`export_cloud`** `{ format?: "ply" | "xyz", path? }` — every vertex with its normal, in the current frame.
Example: `{ path: "C:/parts/_scratch/cloud.ply" }`

**`mesh_inspect`** `{ pieceSize?, holeSize?, deviation? }` — Mesh Tools, where installed: vertices, triangles, closed or not, islands and open rims with their middles.
Example: `{}`

### Pictures and deviation

**`view_render`** `{ view?: "iso" | "top" | "bottom" | "front" | "rear" | "left" | "right", views?: [view, …], fit?, frame?: { min, max } | { at, size } (size: the side of a square fitted in the picture; answers `mmAcross: [w, h]`), show?: { scan?, reference?, sections?, elements?, labels?, … }, section?, width?, height?, path?, inline? }` — a PNG of the viewport; 800 px on the long side by default, up to 2048. `views` (2–6): each fitted and named, side by side in one picture, 1200 px across by default — one look in place of four. In the Reverse engineer `show` also takes `bodies`, `map` (the deviation map on the scan, read against the bodies), `sketches` and `notes` (the pins) — `view_render` puts them back after the picture, exactly as they were, so `{ notes: false, sketches: false }` is a clean deliverable that changes nothing; `false` on a key the workspace on screen lacks is answered `absent: [key]`, not refused; `elements: false` also hides the selection outline and a fit's preview. With `path` the picture is written there too; with `path` and `inline: false` only there, the answer saying where — for deliverables nobody needs to see in the chat. Every picture tool takes `inline`. In the Deviation workspace the answer says what was painted: `map: { on, colormap, range }`, or `map: null` with `mapWhy` (the switch off, no map measured, the reference side not measured, the reference put away, a split view); `mapNote` when the reference drawn over the scan dulls the colours — `show: { reference: false }` gives the clean map.
Example: `{ view: "iso", show: { scan: false }, frame: { at: [20, 0, 10], size: 30 } }` — or `{ views: ["iso", "top", "bottom", "front"], show: { scan: false } }`

**`view_set`** `{ view?, fit?, frame?, show?, section? }` — the same turns and shows, kept; answers every show key standing now.
Example: `{ frame: { at: [12, 3, 8], size: 20 } }`

**`deviation_settings`** `{ range?, maxDistance?, bands?, tolerance?, facingDeg?, colormap?: "jet" | "viridis" | "magma" | "plasma" | "inferno" | "cividis" | "mako" | "rocket" | "turbo", on?: "scan" | "reference", show?, wait? }` — answers the deviation state with `settings.colormap` (the ramp at −range, 0, +range, the caps, the unmeasured grey) and `settings.show`. `{}` only reads it. `show` is the map switch (the view bar's Map key), kept in projects: `false` leaves the surface bare, `true` paints the map again — read it when a picture comes out grey. `on: "reference"` paints the map on the reference — the bodies, after a Compare in Deviation — by its distance to the scan: positive where it stands outside the scan (material the part has not), grey where no scan stands behind it; the state then has `onReference: { spacing, backedPct, withinTolerancePct, farPct, noScanPct, stats }`. `view_render` pictures the side on screen; `on: "scan"` goes back.
Example: `{ tolerance: 0.1, range: 0.3, maxDistance: 1 }` — or `{ on: "reference" }`

**`deviation_hotspots`** `{ tolerance?, patches?, grain?, on?: "scan" | "reference" }` — patches over tolerance, largest and farthest first (centre, box, area, mean, extreme, side), and `far: { inside, outside, count }` past the search distance. `on: "reference"`: the patches of the map on the reference (`outside` = the reference proud of the scan), `far.outside` the reference past the search distance outside the scan, and `noScan: { count, found, patches }` — reference surface no scan stands behind. Read-only.
Example: `{ patches: 12 }` — or `{ on: "reference", patches: 6 }`. Its patches join by distance alone — a uniform offset is one patch over the part; per face, `reverse_body_compare`.

**`deviation_export`** `{ side?: "scan" | "reference", format?: "ply" | "npy" | "csv", path }` — the map as data: a signed distance per scan vertex (or per sample on the reference), binary PLY with `deviation` and `measured`, an N×4 float32 .npy (x, y, z, d) or CSV; d is NaN where there is no reading, and readings past the search distance are kept but unmeasured. Answers `readings`, `measured`, `withinTolerancePct`, `tolerance`, `searchDistance` — the same share the state gives.
Example: `{ side: "scan", format: "npy", path: "C:/parts/_work/dev_r2.npy" }`

**`deviation_open_reference`** `{ path, name?, units?, wait? }` — a STEP, STL, PLY, OBJ or 3MF as the reference part. Not undoable.
Example: `{ path: "C:/parts/bracket_CAD.step" }`

### Reverse engineer: features

**`reverse_feature_add`** `{ feature | features: [feature, …], after?, detail?: "none" | "brief" | "full", wait? }` — `feature` is `{ kind, name?, …fields }` (the kinds below). `features` adds several in order, each built before the next; the first refused stops the rest (`stopped`). `after` inserts right after that feature and rebuilds the rest, one undo step. `detail`: none — id, status, rollback bar, `failed`; brief (default) — the row, a sketch's regions as a point inside each, the bodies changed, and `made: [{ body, faces: [{ index, kind, normal | axis, centroid, radius?, area }], edges: [{ index, kind, length, mid, radius?, faces }], of? }]` — what the feature made, by describe's index, 20 of each at most (`of` counts all); full — the feature as stored, every body, and `made`. Every change also takes `timings: true`: the answer adds `ms` and `steps.played`. A sketch's answer also gives `freeIds`, and `open` when it closes no region.
Example: `{ feature: { kind: "fillet", body: "Plate", edges: [{ between: [[0, 0, 1], [1, 0, 0]] }], radius: 2 }, detail: "none" }`

Also:
- A sketch: `{ kind: "sketch", plane, sketch: { entities, shapes, constraints, patterns } }`, pieces in sheet mm `[u, v]` (Plane frames). An `id` only where a constraint names it (`ids` answers them). `shapes`: `{ kind: "rectangle", center, size }` or `{ from, to }`, `{ kind: "polygon", center, sides, radius, fit }`, `{ kind: "polyline", points, closed }`, `{ kind: "circle", center, radius }`, pieces numbered from its `id` up; `exprs` on sizes (`radius`, `width`, `height`, `length`; not points, not with `fixed`) adds the driving dimension; `patterns` repeats pieces in a row, a grid or round a centre, each copy keeping the pieces’ relations. Ends that meet are joined and level or upright lines held (`infer`, on by default): no coincidences to write; ends under 0.05 mm apart are moved together first, a fixed piece’s too (`snapped`), and a polyline whose last corner lies on its first closes. Fully define it: dimensions with values or expressions, collinear or a distance to `{ datum: "xy" | "yz" | "zx" }` for the origin, or `fixed: true` on a piece or shape placed by its coordinates; `solve.underConstrained` lists the pieces still free.
- A turned part is a revolve: half the profile one side of a line on the axis, about `{ kind: "sketchLine", entity }`; `pitch` makes a coil. An extrude: `extent { kind: "distance", from: 0, to: 12 }`, `op` join (default: one body with every solid it meets), cut or new; `direction: [x, y, z]` sweeps it askew. A thread: `{ kind: "thread", body, face, size: "M3" }` on a full round face (side boss for a bolt, bore for a nut) — ISO metric, UNC, UNF, or `standard: "print45"` with `size: "Ø10"`, a 45° form that prints upright without supports and mates only with itself. Draft leans only the faces picked (a symmetry face stays straight); deleteFace heals the gap a fillet, hole or boss leaves; loft `{ sections, fit: { like }, inner }` fits stations like one made and, with `inner`, a second loft moved in by the wall; sweep runs a sketch’s region along another sketch’s chain; a sheet split or combined with a solid is trimmed before thicken; surface and trim fit a B-spline to a scan region; extract makes a measured element a body.

**`reverse_feature_list`** `{ feature?, detail?: "brief" | "full" }` — rows (id, name, kind, status, message, `warning`, key value, exprs, uses), the rollback bar and the build state; one `feature` whole as stored with its last `result` and, for a sketch, its regions. Exact.
Example: `{ feature: "Plate outline" }`

**`reverse_feature_schema`** `{ kind?, field?, def? }` — a kind's fields as JSON Schema (large shared parts as `$ref`, sized under `refs`; `{ def: "face" }` answers one) and, for the common kinds, an example. Without kind, every kind with what it needs. A schema over 20 k characters (a sketch's, a loft's) answers its fields with their sizes: ask for the one you need by its path — `{ kind: "sketch", field: "sketch.constraints" }`, `{ kind: "cutPlane", field: "plane.radial" }` — never the whole. Once per kind or field.
Example: `{ kind: "draft" }`

**`reverse_feature_update`** `{ feature, set: { …fields, visible?, suppressed?, exprs? } | features: [{ feature, set }, …], detail?, wait? }` — changes a feature as reopening it does; picks by index name the body as it stood before the feature. Below the rollback bar it is edited as an insert is made. `features`: several edits in order, built once after the last, one undo step, each answering its `picked` and `fitted` (a refused one stops the rest: `stopped`). `visible: false` on a feature other than a sketch hides its bodies — out of the view, the export and the comparison.
Example: `{ feature: "Fillet 3", set: { radius: 1.5 }, detail: "none" }` — or `{ features: [{ feature: "Wing station 2", set: { … } }, { feature: "Wing station 3", set: { … } }] }`

Also: `set` takes a boolean’s `body`, `tool`, `op`; a fillet’s `edges`, `radius`; an extrude’s `sketchId`, `extent`, `draftDeg`, `direction`, `op`; a draft’s `faces`, `angleDeg`; a mirror’s `plane`; a sketch’s `sketch` (its whole `{ entities, constraints }`: read with `reverse_feature_list`, change, hand back; a fitted piece keeps its slice points by id), `plane` (any a sketch is made on; u kept where the plane leaves the choice, so regions and a revolve’s axis hold; a fitted piece lets its slice points go, `note`, a projected one is taken again) and `offset`. `suppressed: true` leaves it out of the build. `exprs` works on every kind with numbers — a cut’s or mirror’s `plane.offset`, a loft’s `sections.<k>.offset` and `inner` (`routed`), a surface’s `region.box.min.x … max.z`; a kind with none (boolean, sweep) says so. With `features`, `updated` lists each edit (id, status, result, `picked`, `fitted`), then the bar, the bodies changed and what failed; those before a refused one stand.

**`reverse_feature_refit`** `{ feature, fields?: ["radius" | "distance" | "angleDeg" | "extent.to"], detail?, wait? }` — fits the feature's numbers to the scan again: those fitted this session (the row's `fitted`), or the fields named. Answers as `reverse_feature_update`, with `fitted` and `was`.
Example: `{ feature: "Fillet 3" }`

**`reverse_feature_remove`** `{ feature, detail?, wait? }` — refused while another feature uses it (a sketch on or projected from its body too).

**`reverse_feature_move`** `{ features, after }` — moved to stand after `after`, one undo step, ids, names and picks kept; refused when one would come before a feature it is built on.
Example: `{ feature: 12 }`

Also: a feature builds on its sketch, the body it works on, joins or cuts, the feature that made a face or edge it picks, the body whose face its sketch lies on or whose edges it projects. `detail: "full"` answers every body.

**`reverse_feature_suppress`** `{ kinds?: [kind, …], features?: [ref, …], on?, wait? }` — `on` true (default) leaves them out of the build, false builds them again.
Example: `{ kinds: ["fillet", "chamfer"] }`

**`reverse_feature_rollback`** `{ to?: n | null, after?, detail?, wait? }` — the bar under the first `to` features (null: the end), or after a feature. A revisit is a look-up (`recomputed: 0`).
Example: `{ after: "Extrude 2" }`

**`reverse_feature_clear`** `{ wait? }` — every feature out, one undo step; the parameters stay.
Example: `{}`

**`reverse_sketch_edit`** `{ sketch, add?: { fit?, project?, entities?, shapes?, constraints?, patterns?, infer?, rounds? }, remove?: { pieces?, constraints? }, set?: { <piece id>: fields }, name?, detail?, wait? }` — `set` moves pieces, ids and relations kept. Removals first, then a fit, then the rest, then `rounds: [{ a, b, radius? }]` (an arc tangent to a and b, the scan's radius unless given); answers `solve`, `moved` (`radii`: radii changed, `was`, `now`), `ids` (of pieces given no `id`), `offPiece` (ends slid past the piece they are held on), `warnings` (a picked region grew or took in another), `nearSketches` (pieces under 0.3 mm off another sketch's), `rounds: [{ arc, a, b, radius, sigma, nominal, off, sigmas, residual, points, held: "given" | "points" | "dimension", warning? }]` (`warning`: radius not read — under three points, or at the search's limit), the regions and the bodies changed — `detail: "none"` keeps `rounds`, `accept` and `moved`.
Example: `{ sketch: "Plate outline", add: { constraints: [{ kind: "tangent", a: 3, b: 4 }] } }`

Also: a round at the scan’s radius moves the slice points about the corner that a and b carried onto the arc and the solve fits it, tangencies held — a round a fit merged into its neighbours, put back in one call; `held: "dimension"`: too few points, held at the radius the search came to; `sigma` (mm) how well the points pin it. `remove.constraints` takes relations and dimensions by id. In `add` a pattern may repeat the sketch’s pieces; a piece without an `id`, a shape and a copy take free ones; an id a relation or dimension has is given a free one (`renumbered: { "70": 161 }`). A new end within 0.05 mm of one place other ends lie — and of no other — is moved onto it (`snapped: [{ piece, at, to, by, fixed? }]`), a `fixed` piece’s too: a gap that small is never meant.

**`reverse_sketch_candidates`** `{ sketch, net?: { angleDeg?, mm? }, limit?, pieces? }` — relations the pieces nearly have, with evidence and the constraint ready to add.
Example: `{ sketch: "Plate outline" }`

Also: evidence on every fitted piece — `residual` (rms and worst miss on its points, mm), `sigma` (the fit’s uncertainty: a line’s direction in degrees and place across itself in mm, a round piece’s radius and centre in mm; tight on a long side, loose on a stub), `nominal` (a line’s length and angle, a round piece’s radius, beside the round value a designer would draw, with `off` and `sigmas`). Candidates: `angle` carries `nominal`, `equal` says `what` (length or radius), `onDatum` its `datum`; tangent, equal radius and angle only between neighbours (joined, or ends within a few scatters; equal radius also across one piece and between circles anywhere). `sigmas` = off/sigma: under about 2 within the noise, well over it measured apart. Nearest the mark first; `constraints` is the relation ready to add.

**`reverse_build`** `{}` — waits for the build; every feature with its result, the bodies, `failed`, `buildError`. Read-only.

**`reverse_build_stop`** `{}` — stops a build that does not finish: the kernel started again, the feature whose step was running suppressed (picks kept), the part built without it. Runs while busy. Answers `stopped: { feature, step, call, seconds }` (null with nothing building), `message`, `bodies`, `failed`. A wait at 300 s on one step does the same; `project_load` and `scan_open` with `discard: true` stop a build first.
Example: `{}`

Also: what the session is busy with names the step and how long it has run; `call` is the kernel call ("Splitting"); the save keeps the feature suppressed.

**`reverse_import_step`** `{ path, name?, detail?, wait? }` — a STEP's solids as bodies of their own (an Import feature); put them in place with `moveBody`.
Example: `{ path: "C:/parts/variant_b.step" }`

### Reverse engineer: patch networks

A Patch network is one feature (`kind: "network"`): curves drawn on the scan, the regions they close filled with B-spline patches fitted together — sharing each curve exactly, tangent across it unless it is a crease. Its body is a sheet, or a solid where the network closes. The scan is read as the viewport holds it: page mode only. A curve given is `{ points: [[x, y, z], …], crease?, spans?, along?, side? }` — `points` in order, first end, grips, last end (2 or more), each taken onto the scan; `spans` the span count of the strip of patches running along it (2–20; Auto when left out); `along: { body, edge }` a body's edge it runs on, `side: { body, face, mode: "contact" | "tangent" }` a body's face the patch beside it meets (edge and face picked as a fillet's and a draft's are).

**`reverse_network_create`** `{ curves, fill?: "all" | [[x, y, z], …], name?, snap?, fit?: { smoothness?, robust?, tolerance? }, detail?: "none" | "brief", wait? }` — the curves joined in order: a point within `snap` (0.5 mm) of a node, a grip or the run of a curve given before it is a node of both (the other curve split there; this one cut there when it was a grip). Curves that cross between their points make no node: give the later one a point at each crossing. `fill: "all"` (default) fills every closed region of three to six sides; points fill the regions they lie in. A four-sided cell is fitted as it is; three, five or six sides are split into four-sided ones from the centre. Answers `feature`, `result`, `line` (the box's status line: "4 patches · worst edge 0.02° · worst gap 1.4 µm"), `curves` (the ids each curve given became, in order along it), `joined: [{ given, point, node, on: "node" | "grip" | "curve", of? }]` (`given` the curve's index in `curves`, `of` the curve split), `offScan: [{ given, point, mm }]` (points more than 1 mm off the scan), `openEnds` (nodes one curve end comes to), `patches: [{ patch, rms, max, net: [u, v] }]`, `refused: [{ cell, seed, refused, at? }]`, `unfilled`, `bodies`. `detail: "none"`: id, status, line, curves, rollback. Refused, nothing made, when no region closes ("close no region … N curve ends meet no other — at node …").
Example: `{ name: "Hood", curves: [{ points: [[0, 0, 4], [50, 0, 6], [100, 0, 4]] }, { points: [[0, 40, 5], [50, 40, 7], [100, 40, 5]] }, { points: [[0, 0, 4], [0, 40, 5]] }, { points: [[50, 0, 6], [50, 40, 7]], crease: true }, { points: [[100, 0, 4], [100, 40, 5]] }], fill: "all" }` — two patches, the middle line a crease

Also: a grid is its lines one way, then the other way through their points. A corner is a node where the boundary turns more than 30° (a T-node on a straight run is none). `spans` is Auto from the curve’s length and the scan’s scatter; the first curve of a strip holds where two differ.

**`reverse_network_edit`** `{ feature, set?: [{ curve, crease?, spans?: n | null, along?: … | null, side?: … | null }], move?: [{ node, to } | { curve, grip, to }], remove?: { grips?: [{ curve, index }], curves?: [id], nodes?: [id] }, grips?: [{ curve, at }], add?: [curve, …], unfill?: "all" | [index], fill?, fit?, name?, snap?, detail?, wait? }` — ids and indices as `reverse_network_read` gives them before the edit, done in that order; `spans` sets the strip the curve runs along (null: Auto); `grips` puts a grip into a curve on the run nearest the point; `add` joins curves to the network as create does (`added` gives their ids). A network keeps one filled region. One undo step; answers as create.
Example: `{ feature: "Hood", set: [{ curve: 4, crease: true }, { curve: 1, spans: 8 }], move: [{ node: 5, to: [50, 21, 7.2] }] }`

**`reverse_network_read`** `{ feature, detail?: "full" | "brief" }` — after the last build: `status`, `line`, `counts`, `closed`, `worstAngle` (°, across tangent curves), `worstGap` (mm); `patches: [{ patch, cell, rms, max, net, seed, points, worst: [{ at, off }], dropped?, sides: [[curve ids] × 4], corners }]`; `cells: [{ cell, seed, sides, patches } | { cell, seed, refused, at? }]`; `unfilled: [{ seed, sides }]`; `curves: [{ id, from, to, via, crease?, along?, side?, strip?, gap?, angle? | fold? }]` (gap and angle where two patches share it; `fold` on a crease); `nodes: [{ id, at }]`; `strips: [{ strip, spans, auto, curves }]`; `corners: [{ node, at, patches, angle }]` (where three, five or six patches meet, or four whose tangency could not be held next to the corner — a network drawn askew; near tangent there, its angle read); `openEnds`, `lost`, `ms`. `brief`: status, line, counts, worst, patches' rms/max/net, refused, unfilled. Read-only.
Example: `{ feature: "Hood" }`

Also: `misfit` is what a patch misses the scan by beyond the scan’s noise (past `fit.tolerance` Auto gave its strips more spans where that helped); `dropped` counts the points `robust` left out. `fit.smoothness` (0.001) weighs the fairing of patches and curves against the points: 0 follows them exactly, 0.1 smooths well over the noise, from 1 detail goes; `fit.tolerance` (0.01 mm) is how far Auto lets a patch miss the scan before giving its strip more spans, while that helps — more spans follow more shape, and more noise.

**`reverse_network_suggest_creases`** `{ box?: { min, max }, strongDeg? (25), weakDeg? (12), limit? (40) }` — the scan's sharp ridges and folds traced as crease curves: `candidates: [{ curve: { points, crease: true }, length, angle }]`, longest first (`count`, `more`). Each `curve` goes into `reverse_network_create { curves }` or `reverse_network_edit { add }` as it is; candidates sharing an end share its point. A fillet that rounds a fold over is not offered. Read-only; runs as a job on a big scan.
Example: `{ box: { min: [-60, -40, 0], max: [60, 40, 30] } }`

### Reverse engineer: bodies

**`reverse_body_describe`** `{ body?, edges?, before?, where?, limit?, fingerprints?, sort?: "largest" | "smallest" }` — faces (index, kind, area, centroid, normal or axis, radius, length, side boss/bore, `madeBy`) and edges (index, kind, length, mid, ends, faces either side). `where` filters, `exclude` (a where) leaves out — `exclude: { madeBy: "Thread 1" }` drops a thread's many faces; `limit` caps faces and edges (always, on a patterned body); `before` gives the body as it stood before a feature, a failed one too. A face a pattern copied is `madeBy` the original's feature and carries `copy: { pattern, instance }`.
Example: `{ body: "Plate", where: { kind: "cylinder", diameter: 6.6 }, edges: false }` — or `{ body: "Wheel", where: { sides: { madeBy: ["Blade", "Dish"] } }, limit: 20 }`

**`reverse_body_set`** `{ body, name?, color?, visible? }` — names and colours a body (what a STEP calls it); `visible: false` hides it — out of the view, the pictures, the export and the comparison.
Example: `{ body: 7, name: "Housing" }`

Also: the name is what the panel lists; a body is told by its id, which stays with it while the feature that made it does.

**`reverse_body_section`** `{ plane, offsets?, bodies? }` — the bodies cut at a plane, exact, no scan needed: chains of lines, arcs and circles in its [u, v]. **`reverse_body_probe`** `{ points?, rays? }` — distance to the nearest face (negative inside); a ray `{ from, dir }`'s `span`: a width, a thickness.

**`reverse_body_fillet_read`** `{ body, edges, shape?: "round" | "chamfer", stations?, reach? }` — the round the scan has along each edge, read in cuts square to it at `stations` places (3; 7 on an edge read off the body’s mesh; 9 at most): straight edges between two flats, straight or circle/arc edges between a flat and a cylinder, cone or sphere by their faces’ surfaces, any other edge (a blade’s root on a dish, two curved faces) off the body’s own faces cut at each place. Per edge `{ edge, mid, round: true, radius, sigma, nominal, off, sigmas, residual: { rms, points }, radii, stations: [{ t, at }], linear: { radius: [start, end], rms, medianRms } }` — `sigma` the larger of the fit’s and the spread, `nominal` the nearest half millimetre, `sigmas` |off|/sigma, `t` 0 at the edge’s first end as `reverse_body_describe` lists it (a closed edge from its seam); `rms` well under `medianRms` is a round running evenly from one size to another — `edges: [{ edge, radius: "fit" }]` on a fillet takes it as a variable radius; R2→R10→R2 goes into the profiles. `round: false` with `why` where only some places read one, `places` a verdict each: "R0.8" or why — sharp, no scan, chamfer better, "S-profile: 45 % on the arc", "step 0.8 mm on face 2 — reach ≤ 0.9", "another face 1.7 mm off within the reach — reach ≤ 1.5" (a face ending within the reach holds it to 0.9 of itself); `round: null` for an edge it cannot read; edges no place reads a round on (sharp, the other shape, a gap, a round past the reach) are one row, `sharp: { edges, why }`. `reach` (5 % of the part’s size, 3 mm at least, 5 for a chamfer; a few times the largest round expected) caps the radius: left out, a round at the top of the search, or none, is read again at 2× and 4× (the row’s `reach` says which); given, an empty read says "no round within N mm (reach)" — give a larger one. Then `rounds`, `median`, `spread`. `shape: "chamfer"` (straight traces only): `chamfer`, `distance`, `setbacks` [face0, face1], `setbackSigma`, on a hole’s mouth `countersink: { angleDeg (included), diameter (at the flat face), depth, sigma }`, `chamfers` counted; `distance: "fit"` takes the same edges and `reach`. Needs a scan.
Example: `{ body: "Plate", edges: [{ between: [[0, 0, 1], [1, 0, 0]] }] }`


**`reverse_body_check`** `{ body?, before?, roundTrip?: true | "find", tinyArea?, audit?: "brief" | true | "full" | false, kinkDeg?, stepMm?, parallelDeg?, shortEdge?, limit?, tolerance? }` — `before: feature` checks that feature’s input as the build kept it (a failed round’s or shell’s). Answers `ok`, `problems`, `valid` (the kernel’s check), `closed`, `solids`, `shells` (per solid), `voids` with `voidList: [{ volume, box }]` (sealed cavities — a warning), volume, area; `tiny` (under `tinyArea`, 0.01 mm²: slivers a boolean or split leaves), `narrow` (under 0.01 mm wide, 2 × area / perimeter, which `tiny` misses), `untessellated` (the mesher drew nothing), each by index with area, centroid, kind, madeBy; `edges: { free, nonManifold, contacts }` — free (one face: a hole in the skin) and nonManifold (three or more: a STEP reader sees no closed solid) are problems, a contact (an edge inside its one face, or between faces facing opposite ways) a warning with where and madeBy; `hairs` (`hairEdges`), edges under 0.0001 mm the kernel does not take for degenerate, which a STEP reader may drop; `folds`, a smooth loft’s faces crossing themselves. `readBack` (without `roundTrip`, ≤ 3000 faces): `edges` and `first` (at, length, kind) of what reads back not joining two faces; `closed: false` or `valid: false` with no edge open is a face the reader lost whole, a problem. `roundTrip: true` writes and reads the body as STEP in memory, answering as verify does: `ok`, `problems`, `closed`, `valid`, `faces`, `shells` (body, then file), `gap`, `freeEdges` (at, length, kind, `meet`, the body’s faces at its nearest edge by index with maker; 12, `freeEdgeCount`), `strayShells` (middle, nearest face), `farthest` (no closed solid and nothing open: the body’s point farthest off what came back, and the face lost), `mended` (held by hairs only, as `reverse_export_step` mends it); `"find"` walks the build to the first step whose body does not come back (`find: { step, before, checked, of, done }`, its round trip, faces as they stood there; `done: false` after 30 s). `stepsBetweenFeatures`: steps between faces of two features, hairlines too, 0 on a model whose stacked sketches line up.
`audit` (`"brief"` default): `kinks` — two faces at under `kinkDeg` (5) but not flush; `steps` — two flat faces facing one way within `stepMm` (0.3) but not in one plane, a `round` drawn twice (two rounds on nearly one axis and radius end to end), a round’s `foot` within `stepMm` of another feature’s flat face, or its side passing within `stepMm` through or short of one (`tangent` meant) — a line a pair of features and form, `between`, `count`, the widest’s `off`, `at`, `faces`, `riser`; between features first, hairlines under 0.001 mm their own line, a step under max(0.1, `tolerance`/2) asked about ("meant?"); `nearParallel`, `nearAxis` (within `parallelDeg`, 1), `shortEdges` (under `shortEdge`, 0.1 mm), each with `at`, `off`, faces and edges by index with maker, and a `repair` (a relation, a dimension, a projection); `clean`. `"brief"`: `findings` a line each, `limit` (12) a kind (of steps, lines), `counts`; `true`: lists with `warnings`; `"full"`: with centroids and trace. With `tolerance`, leans under T/2 over a face’s span are left out (`underHalfT`).
Example: `{ body: "Plate" }`

**`reverse_body_compare`** `{ bodies?, range?, detail?: "score", spots?, faces?, patches?, features?, patchVertices?, tolerance?, grain?, within?: { min, max }, far?, feature?, picture?, at?, facingDeg?, unfacing?: "keep" | "drop", skin?: "outer" }` — share read, within, mean, RMS, p50, p95; `patches` (one face each, with box, extreme, side, face, `madeBy`; their vertices only with `patchVertices: true`), `worst`, `faces`, `byFeature` (worst first, `features` of them — 8; 0 leaves it out; `featuresFound` when cut short), and `far: { inside, outside, count, share }` (looked for 25 mm past the reach by default). **Which points:** scan within the reach of the bodies (10 × range: 1 mm at 0.1), the rest under `far`; the Deviation workspace's RMS counts everything within its `maxDistance`, so the two differ — say which you quote. **Which side:** each scan point is read against the nearest surface facing its way within `facingDeg` (90; null: the nearest whatever it faces) — the far skin of a thin wall no longer reads as −t; one nothing faces is read against the nearest (`unfacing: "keep"`) or left out (`"drop"`). `skin: "outer"` reads only the scan facing out of the model — a shell's outer skin before it is hollowed. A sheet is read on its front only (the side its normal faces). `side` counts `refaced`, `unfacingKept`/`unfacingDropped`, `back`, `inward`. `detail: "score"`: the loop's ~3 kB — figures, 5 patches, `far` counts, 3 worst features. Bodies: the visible solids by default; a sheet when named. `volume`: the last `reverse_body_volume_compare` (its totals and two largest regions), or "volume not compared since step N (excess … / missing … then)" when the bodies changed since — run it before going on; `reverse_body_compare_in_deviation` carries it too. Needs a scan.
With `feature`: `{ feature, box, faces, read, within, mean, rms, outside, inside, patches, patchesFound, worst, far, numbers: { field: { feature, scan, sigma, off, sigmas } }, faceRows }` for that feature's faces alone, `patches`, `spots` (0: no `worst`) and `faces` capping each list; `picture: true` adds a section across it as a picture (`picture: { plane, map, gap }`) — square to a round's or chamfer's edge, else through the feature's largest face across its length (a round face through its axis). A feature in several places: `picture.places` lists them and `at: [x, y, z]` picks the one cut.
Example: `{ bodies: ["Plate"], range: 0.1, patches: 12 }` — or `{ feature: "Fillet 4", range: 0.1, picture: true }`

Also: distance positive where the scan stands outside the body. A patch: centre and box (what `view_render { frame }` takes), area, vertices, mean, extreme (its point and vertex; `patchVertices: true` adds a few vertices for `element_fit_marked`), depth (median |deviation|), `volume` (mm³ past the tolerance, the ranking key), `kind` — "feature" at 4 mm² and 25 point spacings² across with depth 2× the tolerance (model or name it, never scatter), else "texture"; never off one face. `worst` spots lie no two within a reach; `faces` give vertices nearest, within, mean, RMS, extremes. Defaults: `patches`, `spots`, `faces` 8, 8, 12; `patchesFound`, `over` count all patches and vertices over tolerance, `features` with `shareOfExcess`; `grain` (three point spacings) joins vertices into a patch. `far: 0` for none; each side its count and patches (the body nearest the extreme, or null). `side` counts `refaced` (read against a surface facing the vertex, not the nearest), `inward` (left out by `skin: "outer"`) and `back` (behind a sheet). `numbers`: a fillet’s radius, a chamfer’s distance, a draft’s angleDeg, an extrude’s extent.to; the picture is a section as `section_render` draws one. `detail: "score"`: the figures (`withinShare` = within/read; `features` without its note), 5 patches to 0.01 mm without vertex, count and side (mean’s sign says the side), `far` counts with 2 patches a side, 3 worst of `byFeature`, `volume`; no `worst`, no `faces`, bodies only when more than one.

**`reverse_body_volume_compare`** `{ bodies?, tolerance?, cell?, regions?, within?: { min, max }, kinds?: ["excess" | "missing" | "unsure"], wait? }` — the volume error of the bodies against the scan, as `deviation_volume` answers it (totals in mm³ and %, `cell`, `smallestSeen`, `found`, the largest regions — 8 by default — with `kind`, `volume`, `maxDepth`, `thickness`, `shape`: `layer` | `lump`, `centroid`, `deepest`, `box`, `evidence`, `confidence`), each region with the `body` and `face` (`index`, `kind`, `madeBy`) nearest its deepest point. Example: `{ tolerance: 0.1, kinds: ["missing", "excess"] }`

(true) }` — the design loop in one call: the volume compare and the comparison at T merged into ranked `places` (`n`, `kind` missing / excess / off, `mm3`, `maxDepth`, `at`, `box`, `face` with its maker, the plan's `region`); a picture of the map at ±T with the places numbered, inline; `vsLast`, `vsFirst`; `target`; `next` (the top place and a first step). Example: `{}`

Also: run it after a build in place of a STEP opened with `deviation_open_reference` (no file, no re-alignment; `deviation_align` may best-fit afterwards). The workspace comes on screen with the map; `deviation_hotspots`, `deviation_settings` and `view_render` read and picture it, `{ on: "reference" }` the body side. Only a reference opened from a file starts the search distance over (`reading.maxDistanceAuto`). `referenceSpacing` is twice the tolerance within 0.25–2 mm (`opened`, with why, on bodies too large to cut so fine); `onReference` patches carry depth, volume and kind. ### Reverse engineer: sections, planes, threads

**`reverse_plane_describe`** `{ plane }` — `origin`, `normal`, `basisU`, `basisV` and `words`. Exact.
Example: `{ plane: { kind: "plane", id: 14 } }`

Also: shapes in a sketch take world points with `world: true`; `element` comes from the fitted patch (`from: "patch"`) or, for a constructed plane, the scan where it meets the plane (`from: "scan"`).

**`reverse_section_fit`** `{ section, chains?, detail?, tolerance?, candidates?, net?, limit?, arcs?, within?: { min: [u, v], max: [u, v] } | { world: { min, max } }, skin?, facing?, closeGaps?, minLength?, maxLength?, closedOnly?, maxChains?, periodic?, plane? }` — `skin`/`facing` as `section_get` takes them, each run fitted as a chain of its own; `maxLength` leaves out chains longer (the outline, to read the holes inside). Without `chains`, the 12 longest (`maxChains`), `leftOut` counting what each filter dropped; `closeGaps` (mm) joins chain ends nearer than that first — a scan full of small holes cuts into open chains — answering `bridged: { gaps, largest }`, a joined chain named by its lowest index with `joined`. Each chain's lines (a, b, length, angleDeg, leanDeg) and arcs (center, radius, start, sweep), with evidence and candidates. A long shallow curve stays an arc when it bows well past the noise. `arcs: n` fits each chain as n arcs end to end — two tangent arcs of near radius the cut takes for one; read each arc's `residual` (a chain that is no n arcs still gets n, badly). `within` fits only what lies in that box on the sheet ([u, v], counted from the part's centre; `{ world: { min, max } }` for a box in world mm), each run in it a chain of its own (`run`); a box that catches nothing is refused with the cut's extent, and the answer's `bounds` is the cut's box on the sheet. The answer's `sketch.add` turns sheet [u, v] into a sketch's on the section (Plane frames). `brief: true` answers each piece as `{ id, kind, radius, world, rms }` and no candidates — for planning over many chains. `periodic: true` reads regular teeth: per chain `periodic` (pitch, riser, depth, crest and trough envelopes with `radiusSigma`, and `shape` — in the sketch frame of `plane` when given, else `world: true`).
Example: `{ section: 3, detail: 0.4 }` — or `{ section: 3, chains: [0], within: { min: [0, -20], max: [110, -5] }, arcs: 2 }`

Also: `detail` 0 (few, long pieces) to 1 (every small feature its own piece), 0.5 by default; `tolerance` (mm) in place of the one read off the chain; world values need no conversion. Evidence and candidates as under `reverse_sketch_candidates`; arcs meeting tangent are offered so. Where the middle of the cut is not the part’s inside, `facing` in place of `skin`. `closeGaps` joins nearest first, two chains’ ends or a chain’s own. `periodic: true` (`within` round one band of teeth): crests and troughs are the extremes about the chain’s trend, each at the corner its two sides meet at; crests are the extremes out of the material (`crestsBy: "material"`) where the cut says which side, else away from the trend’s centre (`"side"`). Per chain: `teeth`, `pitch`, `along` ("u"/"v" of the sheet, or "trend" along the crests’ line or arc), `spread` (rms mm off a regular comb; `note` past 5 % of the pitch), `riser` and `facet` (the shorter and longer part of a tooth), `crestToTrough`, `depth` (mean, min, max), `crests`/`troughs` (envelope: an arc’s center, radius and `radiusSigma` — a short arc of a large circle fits at many radii, so the profile is surer than the radius — or a line’s point and angleDeg; rms, worst, corners, in the world too), `first` (kind, at, `s` along the pitch — a Fresnel’s first ring radius on u), `profile` (count, `sheet`), `shape` (open polyline for a sketch’s shapes: in the sketch’s [u, v] with `plane`, else `world: true`), `fit` (rms, worst). The sketch closes it into a region with its other pieces; revolved, it makes the faces.

**`reverse_section_stack`** `{ plane, offsets: [mm, …], within?: { min, max, clip? }, skin?, facing?, axis?, closeGaps?, minLength?, maxLength?, closedOnly?, maxChains?, detail?, tolerance?, pieces? }` — up to 60 cuts, each chain summed up (closed, centroid, area, size, `circle { center, radius, rms }` where a fitted circle holds within the chain's own noise), and `tracks` (tiltDeg, draftDeg per side, taperDeg, round with rms against linearRms). `within` keeps a chain with any point in the box, whole; `clip: true` only what lies in it, each run a chain. `skin`/`facing` as `section_get`. `axis: { kind: "element", id | name } | { kind: "world", axis }`: each chain and track level gives `fromAxis { mm, towardDeg }` — a dish's drift off the bore, height by height. On a holey scan `closeGaps: 0.5`, `minLength: 2` and `closedOnly` keep the answer to the outlines that matter. Needs a scan.
Example: `{ plane: { kind: "world", axis: "z" }, offsets: [2, 4, 6, 8, 10], within: { min: [10, -10, 0], max: [30, 10, 12] } }`

Also: a `circle` holds within twice the chain’s noise or 0.4 % of its radius. A track starts anew where a chain opens or closes, or its box or area changes by more than about 30 %; `tiltDeg` is the centre’s drift per mm, `draftDeg` the width’s and height’s growth per mm (positive with the offset), `taperDeg` a circle’s radius per mm (a cone’s half-angle), `round` the radius the width follows better than a line (a fillet or dome, from four offsets). `fromAxis.mm` is from the circle’s centre, else the centroid, to where the axis crosses the cut, `towardDeg` from +u towards +v.

**`reverse_section_outline`** `{ section | plane, chain?: n | "largest" | { at: [u, v] | [x, y, z] }, within?, maxLength?, tolerance?, closeGaps?, skin?, facing?, snapDeg?, simplifyDeg?, maxPoints? }` — one chain (with `skin`/`facing`, one run of it) (the largest by default; `{ at }` the chain within 3 × its scatter of that point — an opening's rim gives the opening —, else the closed one round it, else the nearest; `within` and `maxLength` as on `reverse_section_fit`) thinned to a polygon within `tolerance` (default max(0.05, 3 × its scatter)), ends nearer than `closeGaps` joined first, sides within `snapDeg` of u or v laid exactly along them: `shape: { kind: "polyline", closed, points }` **in the sketch's frame** on that plane — paste it into a sketch's `shapes` as it is — with `count`, `maxDeviation`, `bridged`. In place of reading corners off a picture — for a throw-away cutter only: an outline the part shows is lines and arcs (a sketch `fit`). `simplifyDeg` (2–3 for a cutter) takes out corners turned by less, gentlest first, answering `merged` — a chamfer along the cutter then meets no near-tangent crease; check `maxDeviation`.
Example: `{ section: 3, chain: "largest", closeGaps: 1, snapDeg: 2 }`

Also: `{ at }` takes `[u, v]` in the sketch or `[x, y, z]` in the world, taken square onto the plane (`at` says where it came out, `offPlane` how far off). `maxLength` leaves out the part’s outline so `largest` is the largest opening in it (`leftOut` counts). With `skin` or `facing` the chain by index is its longest run, `largest` the longest run, `{ at }` the run it names. Thinned by Ramer–Douglas–Peucker, the tolerance raised until at most `maxPoints` (200) corners; `snapDeg` lays each side at the mean of its points, a run of such sides one side, the corner square where a level side meets an upright one (`snapped`). On a measured plane `element` says where the element lies in those [u, v] (centre, box): zero is the world origin’s foot, not its centre.

**`reverse_thread_read`** `{ axis: { kind: "element", id } | { kind: "face", body, face } | { kind: "line", origin, dir, radius, length }, standard?: "metric" | "unc" | "unf" | "print45" | "any", band?, length?, limit?, profile? }` — `thread` (a pitch, and teeth — `contrast`, mm — at least three times the wall's `noise`), pitch, minor, major, internal or boss, hand, candidates, `suggested`, and along a face `feature` ready to add (left hand only at `handConfidence` ≥ 0.2). Read in windows: `windows[]`, `agree` (trust ≥ 2), `threaded` [from, to] where minor and major are read, `offWall`; along a face its coaxial run (`run`). The radius curve only with `profile: true`.
Example: `{ axis: { kind: "face", body: "Plate", face: { kind: "cylinder", near: { at: [20, 0, 4], radius: 3 } } } }`

Also: `minor` and `major` are the 5th and 95th percentile of the radius, each sector of the wall about its own level. `strength` (0–1) is how well the profile repeats, `contrast` the profile folded at the pitch, peak to peak. `windows[]` give `from`, `to` (mm along the axis from the middle), pitch, strength, contrast; `agree` is 0 where only the whole length reads one, a pitch too coarse for a window; a hole threaded half its length, or chamfered at its mouth, still reads. `offWall`: points facing along the axis (chamfers, rims), left out; `run`: the faces on the axis beside the one given (a hole cut in pieces, its countersink, a thread’s flanks). `band` is 0.6 mm or a fifth of the radius; `profile` is 200 points.

Picks: a face or an edge is an index from `reverse_body_describe`, a fingerprint, or a `where` query, written as the pick itself (`edges: [{ sides: { madeBy: ["Blade", "Dish"] } }]`; a `{ where: { … } }` wrapper is taken the same) — `box`, `near`, `kind`, `between` (normals either side; one or two), `withinDeg`, `madeBy`, `faces: [i, j]`, `minLength`/`maxLength`, `minArea`/`maxArea`, `radius`/`diameter` with `sizeWithin`, `exclude` (a where or indices, taken out of what matched), `loop: "outer" | "inner"` with `faces: [i]` (a flat face's rim, or the rims of its holes), `coaxial: { at, dir, within? }` (circle edges and round faces on that axis — a bore's wall, its countersink and both rims in one), `through: { at, within? }` (edges passing within 0.01 mm of a point, anywhere along them), `sides: { madeBy: [A, B] }` (edges between the faces of two features; pattern copies count as their original's), `sharp: true` (edges whose faces meet at an angle — a round's seams left out), `optional: true` (may match nothing). `between` with one normal matches every edge beside a face facing that way, round faces by their axis too: narrow it with `faces`, `loop` or `exclude`. A change answer's `picked` (brief, full, and with `detail: "none"` too) says what each index or query landed on (kind, size, place), and `chains`/`smooth` when its edges make fewer tangent chains than they number — check it when a pick was an index read before the last change or an `after:` insert. Feature names are unique: a name in use is refused. Numbers may be driven by `exprs: { "extent.to": "t" }` — a cut's or a mirror's plane by `"plane.offset"`, a loft's and a surface's as in their rows; a kind with no numbers (boolean, sweep) says so; an extrude's lean by `exprs: { draftDeg: "draft" }`, the field's sign (positive leans in). A body is named by its id, its name, or the name of the feature that made it; an id sent as text (`"185"`) works where nothing has that name.

Also: a name matches whole, case aside. `through` finds the edge a chamfer or round in a mesh stood on; `withinDeg` is 10 by default; `faces` are indices on the body the query is run on; `coaxial` takes cylinders, cones, tori and spheres (by centre) parallel within 1°, `within` 0.05 mm of the line; `sizeWithin` is 2 % of the radius, 0.05 mm at least; `optional` is for many picks read off a mesh, a few of which may not be in the model; a round’s seams match a radius as the edge they rounded did; the terms may be nested once more under `where`. `reverse_body_describe`’s `limit` gives the first that match, or with `sort` the largest or smallest (the mounting face, the longest edge).

## Plane frames

A sketch's pieces are [u, v] mm on its plane; world = origin + u·basisU + v·basisV, and back u = (p − origin)·basisU, v = (p − origin)·basisV. The normal is basisU × basisV: the way an extrude goes, and positive offsets.

| Plane | Shape | u | v | Normal | Offset |
|---|---|---|---|---|---|
| XY | `{ kind: "world", axis: "z", offset? }` | X | Y | +Z | the Z coordinate |
| YZ | `{ kind: "world", axis: "x", offset? }` | Y | Z | +X | the X coordinate |
| XZ | `{ kind: "world", axis: "y", offset? }` | Z | X | +Y | the Y coordinate |
| Section | `{ kind: "section", id \| name, offset? }` | as on the coordinate plane it lies in (not the section's sheet — see below) | | the section's normal | mm along it |
| Measured plane | `{ kind: "plane", id \| name, offset? }` | the sketch frame: zero at the world origin's foot, not the element's centre | read it | the element's normal | mm along it |
| Through an axis | `{ kind: "radial", axis: { kind: "element", id \| name } \| { kind: "world", axis }, angleDeg, offset? }` | out along the radius | up the axis (toward the + end of the nearest coordinate axis) | u × v | mm along it |
| Body face | `{ kind: "bodyFace", body, face, offset? }` | the coordinate axes flattened onto the face, as on the coordinate plane it is nearest to | | outward | mm out of the face |

- On a coordinate plane — and in a sketch on a section, or in `section_render { plane }` — the sheet's zero is the part's origin projected onto it.
- **`up: "x" | "y" | "z"`** on a world, section, plane or body-face ref sets u = up × normal, so v runs up that axis on any standing plane, whichever way its normal points. A radial plane's angle: 0° is the next coordinate axis round (X about Z, Y about X, Z about Y), right-handed; 52° and 232° both have v up and u out. A sketch on a section cut `{ axis, angleDeg }` takes the old section rule: use `{ kind: "radial" }` or `up` for that frame.
- **A section's own sheet counts from the part's centre**, not the origin: what `section_get`, `reverse_section_fit` and `section_render { section }` give in [u, v] is off a sketch's [u, v] by the centre. `reverse_section_fit` answers `sketch.add` — sketch [u, v] = sheet [u, v] + add — and every piece's `world` values; take those, never a sheet number typed into a sketch. A sketch with `fit` converts by itself.
- **A sketch on a measured plane counts from the world origin's foot**, not the element's centre (75 mm away on the last mirror holder). Its answers, `reverse_plane_describe` and `reverse_section_outline` give `element: { centre: [u, v], box }`: draw about it; `farFromElement` means the pieces are misplaced. `scan_heightmap`/`scan_outline` on an element share the sketch's [u, v] (`flipped: true`: seen from behind).
- **Read every non-coordinate frame with `reverse_plane_describe` before computing [u, v]**: it answers origin, normal, basisU, basisV to the last digit and says in words which way u and v run. An element's own `basisU` (from `element_fit`) is the fitter's axis, not a sketch's u; `section_render { plane: <element> }` cuts in the sketch's frame — pass the element, not a rounded normal.
- **Sketches on body faces** follow the face when an earlier feature moves it, standing off it by the offset. Pick the face by a `where` query rather than an index when the body may still change. A sketch on a body face is found again at build time; its projected pieces are taken again from their sources.
- For a tilted face, make a `plane-coords` element from exact numbers and sketch on `{ kind: "plane", id }`.
- `reverse_section_stack` offsets: on a coordinate plane the coordinate itself, on any other plane mm along its normal.
- Mirror and draft planes also take `{ kind: "face", face }`: a flat face of the body worked on.
- Revolve axes lie in the sketch plane: `{ kind: "sketchLine", entity }` (usual), `{ kind: "world", axis }`, or `{ kind: "element", id }`.
