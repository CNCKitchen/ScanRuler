# Measuring a 3D scan — reference

The shapes behind the measure guide. Every tool is a ScanRuler command with dots turned into underscores (`element.fit` is `element_fit`), plus the server's own four (`scanruler_status`, `scanruler_open`, `scanruler_wait`, `scanruler_batch`). Inputs are JSON; lengths in mm, angles in degrees. A field marked `?` is optional. An element, dimension or section is named by its id or by its name as the list shows it ("Plane 1").

**How answers come back.** JSON, numbers kept to six significant digits. A refusal comes back as text `code: message`, marked as an error; in a batch as `{ tool, ok: false, error: { code, message } }` (see Errors). A tool that takes a file takes `path` (absolute, or relative to the agent's folder) and the server reads it; a tool that hands a file back takes `path?` and the server writes it there, answering where and how large.

**Every tool that changes the session** is one undo step, takes `wait?` (`false` answers `{ queued: true, job }` at once), and runs as a job the server keeps.

## Command shapes

### The server's own tools

**`scanruler_status`** `{}` — `backend` ("page" or "headless"), `connected`, `page: { app, version, origin, plugins, viewport, hidden, commands }`, `server` (`server.role`: `holder` — this copy holds the tab's connection; `relay` — another copy, another chat or AI app, holds it and this one sends its calls through it, `server.holder.version` saying which; `none` — neither yet, `server.error` saying why; the work runs in the tab either way), and when it applies `howToConnect`, `hiddenNote`, `jobs: [{ job, tool, state: "running" | "done" | "failed", ms | runningMs }]`, newest first, the last 50 kept.
Example: `{}`

**`scanruler_open`** `{}` — opens ScanRuler in the person's browser, paired, and waits; answers the status with `opened`. The first time the browser asks whether the site may reach apps on this computer; they must allow it.
Example: `{}`

**`scanruler_wait`** `{ for?: "page" | "idle" | "job", job?, timeoutSeconds? }` — until a page is connected (default), until it is also idle, or until a job is done — then `{ job, tool, state, ms, result }` or `{ …, error: { code, message } }`, `state: "running"` if the time ran out. 120 s by default, 600 at most.
Example: `{ for: "job", job: "j7" }`

**`scanruler_batch`** `{ calls: [{ tool, arguments? }], stopOnError?, rollback?, timings?, wait? }` — up to 200 calls in order (not the server's own four). Answers `{ results: [{ tool, ok, result } | { tool, ok: false, error }], ran, of }`, and when stopped `stopped` and `failed: { index, tool, error }`; with `rollback` (default true) the changes made before the refused call are undone and listed in `undone`, newest first; `rollback: false` keeps them; `stopOnError: false` runs every call and reports each. `timings: true` adds each result's `ms` and the batch's total_ms. A picture is not shown in a batch: it is written to a file — the call's `path`, or a new file in the server's output folder — and its result's `file.path` says where.
Example: `{ calls: [{ tool: "element_fit", arguments: { kind: "cylinder", at: { point: [20, 0, 5] } } }, { tool: "element_fit", arguments: { kind: "cylinder", at: { point: [-20, 0, 5] } } }, { tool: "dimension_add", arguments: { refs: ["Cylinder 1", "Cylinder 2"] } }] }`

### Session and history

**`session_state`** `{}` — the whole session: app and plugins, workspace, `busy`, the scan (file, units, counts, bounding box, centre, size, alignment), elements with fits, dimensions with values and verdicts, sections, deviation, thickness and 2D state, the guided hint, the undo history. Read-only; answers while a change runs.
Example: `{}`
Details: `project.name`; `project.unsaved` — changes not saved since the project was last saved or opened, as the top bar's "Unsaved changes" says (null with no page); `project.holds` — the work a new scan or project would replace, counted by what it is; what is open in the panels; `ui.units` — what the screen shows lengths in, `mm` or `in`. The screen may show inches; every answer of every tool is in millimetres, angles in degrees. Read the state before acting and after.

**`scan_open`** `{ path, name?, units?: "mm" | "cm" | "m" | "in", discard?, wait? }` — an STL, PLY, OBJ, 3MF or STEP as the scan; answers name, units, counts, bounding box, centre, size. Refused over measurements unless `discard: true`. Not undoable.
Example: `{ path: "C:/scans/bracket.stl", units: "mm" }`
Details: a STEP part is cut into triangles, a few hundred to the part's diagonal. `name` is what the session calls the model (the file's own name by default). `units` are the file's coordinates: an STL carries no units of its own; PLY and OBJ are taken in millimetres unless told otherwise; everything is measured in millimetres once read. Everything measured on the old scan goes with it — the refusal names what the session holds. A reference part opened from a file stays, its alignment and maps gone (`referenceKept` names it); one the app made from the session's own work goes with that work (`referenceDropped`). The answer's `bounds` are the box's min and max corners, `center` its centre, `size` its diagonal, mm. A new scan starts a new history.

**`session_reset`** `{ discard?, wait? }` — closes scan, reference and image. Not undoable.
Example: `{ discard: true }`
Details: with them every measurement and the project's name go, as opening an empty project does; the history starts over.

**`session_recent`** `{ job?, limit? }` — what became of the commands the server ran under its jobs (each change and each batch is one), newest first: job, command, `running` | `done` | `failed`, when it started, `ms`, and its result or `error { code, message }`. A result past 16,000 characters is left out (`resultOmitted` says its size); the page keeps the last 100 while it stays open, so a server started after the one that asked can still read what a job did. `limit` 20 by default. Read-only.
Example: `{ job: "j7" }`

**`workspace_set`** `{ workspace: "measure" | "deviation" | "thickness" | "flat" | … }` — puts a workspace on screen for the person.
Example: `{ workspace: "measure" }`
Details: measure (fitting elements and dimensions), deviation (scan against a reference part or an element), thickness (wall thickness), flat (2D measuring of an image or a section), or a plugin's by its id — `session_state` lists them under `app.plugins`. Commands put their own workspace on screen; this is for showing the person something.

**`history_checkpoint`** `{}` — marks where the undo history stands; answers `{ checkpoint, top, steps }`. Changes nothing.
Example: `{}`
Details: made before a run of changes that should stand or fall together; `top` is the step on top, `steps` how many there are.

**`history_restore`** `{ checkpoint, detail?, wait? }` — undoes every step since that mark, newest first; answers `{ undone, after }` (`detail: "full"`: `state`, the whole session). Refused, undoing nothing, once the mark is gone.
Example: `{ checkpoint: "cp2" }`
Details: each step as the undo key would take it, one by one, so a run that went wrong in the middle is taken back whole. The mark is gone when the history was undone past it, or started afresh (a scan or a project opened).

**`history_undo`** `{ detail? }` and **`history_redo`** `{ detail? }` — one step back or forward; answer the step's name and `after`, the session in brief (`detail: "full"`: `state`, the whole of it).
Example: `{}`
Details: a step is one of the person's or one of these commands, each of which is one step. Refused while something open in a panel is in the way.

### The scan

**`scan_nearest`** `{ at: { point: [x, y, z] } | { vertex } }` — the vertex, its coordinates and outward normal, a triangle, the distance from the point. Read-only.
Example: `{ at: { point: [12, -4, 30] } }`
Details: a place anywhere is `{ vertex: n }` (a scan vertex, as a project file and `session_state` name it) or `{ point: [x, y, z] }` (mm, in the frame the part is measured in now; the nearest scan vertex is taken). `{ screen: [x, y] }` (a viewport pixel, x right and y down from the top left, as on a `view_render` picture) and `{ candidate: n }` (a feature from scan.candidates) are named in the contract and refused as not implemented until they arrive. Use `scan_nearest` to check a point lies on the surface before fitting there.

**`scan_query`** `{ box: { min, max } | near: { at, radius }, normal?: { dir, withinDeg? }, limit?, mark?, fields?: "count" | "ids" | "all" }` — vertices in a box or ball, optionally facing a direction (within 30° by default); at most `limit` (1000 by default, 20000 at most), evenly thinned, `step` saying how. Answers `matched`, the vertex numbers, points, normals, box, centroid, mean normal.
Example: `{ box: { min: [0, -20, 9], max: [40, 20, 11] }, normal: { dir: [0, 0, 1] }, limit: 5000 }`
Details: the points on a face, to measure a dimension or a draft angle off, or to see what the scan has where a model is being built; the box is in the frame the part is measured in now. Past `limit` every k-th matching vertex is kept, spread evenly, and `step` says k. The vertex numbers are what `scan_nearest` and `element_fit_marked` name. `fields: "count"` gives the numbers alone (`matched`, `returned`, `step`, `bounds`, `centroid`, `meanNormal`), `"ids"` adds the vertices, `"all"` (the default) the points and normals too — but with `mark` the default is `count`. `mark: true` leaves every vertex that matched marked — all of them, not the thinned list; `marked.points` counts them — for `element_fit_marked { marked: true }` and whatever else takes the marked points, so the list need not come back at all. Changes nothing on the part.

**`scan_fit_surface`** `{ vertices? | box?, normal?: { dir, withinDeg? }, model?: "plane" | "bilinear" | "quadric" | "best", limit? }` — a patch of the scan measured as a surface: a sloped side, a twisted ruled face, a dome, a saddle, a fairing. Read-only.
Example: `{ box: { min: [0, 0, 0], max: [30, 30, 12] }, normal: { dir: [0, 0, 1] } }`
Details: the points come as `vertices` (from `scan_query` or a patch; reading them by number needs the viewport) or as a box (`normal` keeps those facing a way, within `withinDeg`, 30 by default); 7 points at least, at most `limit` (20000) spread evenly. The best plane through them sets the patch's own frame: `origin` at their centroid, `normal` out of it, `basisU` and `basisV` in it, all in the frame the part is measured in now. Each model is a height over (u, v) along the normal: plane `h = a + b·u + c·v`; bilinear `+ d·u·v` (a hyperbolic paraboloid: a straight-lined twisted face); quadric `+ d·u² + e·u·v + f·v²` (a dome, bowl, saddle or a cylinder's strip). Each answers its `coefficients`, `rms` and `worst` (mm off along the normal); the quadric also `curvature`: `k1` and `k2` (1/mm, the larger first), `r1` and `r2` (their radii, null where flat), `axis1` and `axis2` (their directions in the world) and `shape` (flat, cylinder, dome or saddle) at the patch's middle. `model: "best"` (the default) fits every one and `best` names the simplest whose rms is within a tenth of the lowest — the model that holds, plain.

**`scan_draft`** `{ pull: [x, y, z], box?, nearDeg?, patches?, minArea?, split? }` — the walls that run near a pull direction, as patches with the angle each leans off the pull. Read-only.
Example: `{ pull: [0, 0, 1], nearDeg: 10, split: "symmetry" }`
Details: each patch has `draftDeg` — positive where the wall faces partly along the pull (it lets go as the tool moves that way), negative where it faces back (a back draft, an undercut to that pull); `sigmaDeg` its standard error; `spreadDeg` the points' own spread (mostly the scan's normal noise); `centroid`, `box`, `area` (mm²), `count`; `facing` (which way the wall faces across the pull) and `turnDeg` (how far that turns across the patch). Neighbouring walls are parted where the way they face jumps, so a box's four sides are four patches and a thin wall's two sides (a blade, a rib) two patches facing opposite ways; a point joins a patch only while it faces within 20° of the patch's mean, so a smooth freeform wall comes in patches that turn 40° at most. A boss's or a hole's round side is one patch with `round: true`, its facing no one way. `pull` is any length; `box` keeps only the scan inside it; `nearDeg` is how far off square to the pull a wall may lean and still count (10 by default, 45 at most); `patches` how many, the largest first (12); `minArea` leaves smaller ones out (1 mm²). `split` keeps every patch to one side of a plane: `"symmetry"` (the scan's mirror plane: the last measured symmetry plane, else searched for — refused when the scan has none), a plane element by name or id, `"XY"`, `"YZ"`, `"XZ"`, or `{ point, normal }`; each patch then says its `side` (1 along the plane's normal, −1 against) and the answer gives the plane (`split: { point, normal, from, rms? }`). The answer also gives `pull`, `nearDeg`, `points`, `walls` and `found`. Read it early on a moulded or cast part, along each direction the tools open: walls that lean half a degree to a few explain fits that miss by the lean.

**`scan_heightmap`** `{ axis?: "-z" | "+z" | "±x" | "±y", plane?, flip?, box?, of?: "height" | "deviation" | "relief", smooth?, cell?, grid?, levels?, gap?, slopeDeg?, picture?, path? }` — where the scan is first met looking along an axis or square onto a plane, over a grid of cells. Read-only.
Example: `{ axis: "-z", box: { min: [0, 0, -5], max: [40, 30, 20] }, levels: true }`
Details, the axis: `-z` (the default) looks down from above and gives the top surface's z; `+z` looks up from below and gives the underside's; ±x, ±y likewise. Cells lie on the two other axes in order — x, y for z; y, z for x; x, z for y — as u and v. The plane, in place of `axis`: a plane element (id or name), a coordinate plane `"XY"`, `"YZ"`, `"XZ"`, or any other — a face of a model, say — as `{ origin, normal, u? }`; the map then looks down the normal onto it, height is the distance from the plane along the normal, and u, v are the plane's own, laid as a sketch on that plane has them (`section_render { plane }` draws the same sheet) — `u` seeds its direction. A plane element's normal is turned to the side the scan is not, so the map looks at the face it was fitted on; `flip` turns it over. Either way u and v stay the sketch's — a point has the same [u, v] in the map as in a sketch on that plane — and when the map looks against the sketch's normal, `plane` says `flipped: true`: its normal is the way looked from, and the map is the sketch's sheet seen from behind (u, v, normal left-handed). The answer's `plane` gives its frame in world: a cell's point is `origin + u·U + v·V + height·normal` — and, for an element or a plane given by its origin, `center`: where the element's centre (or that origin) lies in [u, v], for the frame's zero is the world origin's foot on the plane, not the element's centre.
The box: the part looked at, the scan's box by default; rays start at its face and stop at the far one. With `plane`, `box` is in the plane's frame — `min` and `max` are [u, v, height], and by default it takes in the whole scan — or `box: { world: { min, max } }` gives it in the world, [x, y, z]: the map takes the box round its corners in the plane's frame, so a box round a place on the part needs no working out. Where under a fifth of the cells meet the scan, `scanLies` says where the scan lies in the map's frame (min and max, [u, v, height] — or along the axis looked) beside the grid's span.
`of`: `height` (the default); `deviation` — the scan's signed deviation where each ray lands (the map `deviation_align` or `deviation_set_target` measured, read off the triangle met), null where the map has no reading within its search distance, with `source` and `searchDistance` in the answer; `relief` — the height less the surface round it (at each cell a plane fitted to its neighbours, weighed by a Gaussian `smooth` mm wide, three cells by default; make it about the width of what is looked for): icons, grooves, lettering and parting lines stand out of a face that curves or leans, positive proud and negative sunk. `cell`: mm (by default a round size that makes 40 cells on the longer side, widened to keep 1600 cells at most — and 160 and 25,600 when the numbers are not returned; `note` says when it was widened).
The answer: `along`, `across`, `cell`, `origin` [u0, v0] (the grid's low corner), `cols`, `rows` and `grid`: rows of values (mm; heights to 0.01, deviation and relief to 0.001) from the low v up, null where there is none — `grid[r][c]` stands at `u0 + (c + ½)·cell, v0 + (r + ½)·cell` — with `min`, `max`, `hit` (cells met) and `valued` (cells with a value). `levels: true` returns, in place of the grid, the values gathered into levels — a pad's tiers, a pocket's floor, the face round them — the largest first (12 at most, `moreLevels` counting the rest): each its `height` (the median), `sigma`, `range`, `cells`, `area` (mm²), `sharePct` of the cells counted, and `box` ([u, v] min and max); of a height, each level of 5 % or more also its `plane` { origin, normal } — fitted to its cells, the normal towards the viewer — which `align_datum { primary: { plane } }` levels on. A height whose levels a gentle warp ran together (a stamped sheet and its bead crowns, a bent plate) is read again with a smooth surface fitted to the largest level taken out; `warp { rise, bow, note }` says so, and the heights are then read off that surface (the gaps between levels are the steps). Of a height, the cells sloped more than `slopeDeg` (10° by default; 90 keeps every one) are left out first and counted as `sloped` — a fillet's ramp, a cone, a wall met at a glance — so two tiers a ramp joins stay two levels; a face that leans more is read by looking square onto it (`plane`). Two levels lie at least `gap` apart (mm; three times the cell-to-cell `noise` on the cells counted by default, 0.02 at least), and `unassigned` counts the cells counted that fall in none (walls, edges). Where the sloped cells are more than a fifth of those with a value, or one run of them borders a single level (a ramp off a tier that meets no other), `ramps` says so — "ramps between tiers (sloped 34 %) — a section along them gives their profile" — with `found` and the largest runs: `cells`, `area`, `box` and `joins` (the heights of the levels each borders). `grid: true` keeps the grid as well as the levels; `grid: false` leaves it out and returns the picture. `picture: true` adds the map coloured by its values with coordinates in the margins and a scale (a deviation in the workspace's colour map over its range); it needs the browser.

**`scan_outline`** `{ axis?, plane?, flip?, box?, tolerance?, loops? }` — the scan's outline seen along an axis or square onto a plane, read as a sketch would draw it: a flange's plan, a bezel's opening, a gasket's shape. Read-only.
Example: `{ axis: "-z", tolerance: 0.2, loops: 2 }`
Details: rays over a grid of cells (half the tolerance, widened to keep 250,000 cells at most — `note` says so, and the outline is then read to the cell; a box round the part looked for reads it finer) find where the scan is and where it is not; the line between is traced round and each loop read as the fewest lines and arcs that follow it within `tolerance` (mm, 0.2 by default): straight sides are fitted as lines and met at sharp corners; an arc between two sides is that corner's round (`rounds`: `at`, the corner's index in `points`, `radius` and `center`); any other arc is a side of its own (`arcs`: `from`, the index of the point it starts at, running to the next, `radius`, `center` and `mid`, the point halfway along it) — a slot's ends: draw it as a three-point arc from `points[from]` through `mid` to the next point; where the centre lies near the chord (a half-round end), only `mid` says which way it bulges; and a loop that is round all the way is one `circle { center, radius, rms }`. `axis`, `plane`, `flip` and `box` as `scan_heightmap` takes them, `box: { world: { min, max } }` too; the coordinates are u, v as it lays them (the two other axes in order, or the plane's own; `plane.center` is the element's centre in them). Loops come the largest first (`loops`: how many, 4 by default; `more` counts the rest): each with `hole` (true for one inside another), `area` (mm²), `box`, `points` ([u, v] corners in order), `rounds` and `arcs`, or `circle`, and `worst` — how far the traced outline strays from what is drawn, mm, with `worstAt` where, when it is past the tolerance.

**`scan_pattern`** `{ axis, at?, radius?: { min?, max? }, maxCount?, instances? }` — rotational repeats about an axis — a fan's blades, a flange's holes and pads, a wheel's spokes, a gear's teeth — counted from the scan. Read-only.
Example: `{ axis: "Bore", at: [4, 12], radius: { min: 20, max: 45 } }`
Details: the scan is cut square to the axis at each height in `at`, and each cut (only what lies between `radius.min` and `radius.max`) is turned against itself. `count` is the number of copies whose outlines land on each other going round (up to `maxCount`, 60 by default, 120 at most); `pitchDeg` 360/count; `phaseDeg` where the first copy's middle lies (under one pitch), `betweenDeg` midway to the next — angles about the axis as `section_cut { across: { axis, angleDeg } }` takes them: 0° the coordinate axis next round (X about Z), turning by the right hand. `score`, 0 to 1, is how well the copies' outlines land on each other; under 0.5 nothing is taken to repeat and `count` is 1 (`tried` gives the best count and its score). Each copy in `instances`: `angleDeg` and `radius` of its outline's middle, `offDeg` from where an even spacing puts it, `rms` and `worst` — how far its outline lies from the other copies' turned onto it (the median over them), mm — and `share`, its outline's length against the median copy's (well under 1: the scan misses part of it, or the copy is not there); `rms`, `worst` and `worstInstance` over all the copies; `instances: false` leaves the copies out. Round outlines about the axis — a bore, a hub, a rim — are not copies: they come back as `rings`, each its `radius`, `off` (how far its centre lies off the axis, mm), `towardDeg` (which way) and `rms`. `axis`: a cylinder, cone, line or circle element by id or name, a coordinate axis `"X"`, `"Y"` or `"Z"` through the origin, or `{ origin, dir }`; its direction is turned to the + end of the coordinate axis it lies nearest and its origin put at the world origin's foot on it, so a height along it is the coordinate itself on a coordinate axis (the answer's `axis` gives `origin`, `dir` and `zeroDir`). `at`: heights along the axis, mm, or points [x, y, z] in the world, each the height of its foot on the axis; by default 6 spread over the scan, 12 at most. Features lie at different heights and radii: cut through each, and keep `radius` to the ring one lies in where two share a height — in one cut the feature with the most outline sets the count, and the other reads as what its copies miss (`worst`).

**`scan_qa`** `{ axis?: "x" | "y" | "z" | [x, y, z] }` — one call before modelling, to know what the scan will and will not give. Read-only.
Example: `{}`
Details: `rims` — the open edges of the scan's holes: `count`, `total` length, the `largest` few with their number `rim`, `length`, centre `at` and `size` (mm), and `circles`: other rims a circle fits (a hole the scan did not see into, `moreCircles` counting the rest). A rim that lies on a circle has `circle { center, axis, radius, rms }` (rms its scatter off the circle, mm), and `element_fit { kind: "circle", rim }` makes it an element. `noise` — the median scatter of small plane fits round a sample of vertices (mm; near 0 is a CAD tessellation) and its `p90`. `thickness` — through the part along `axis` (x, y, z or a direction; by default the alignment's z when the part is aligned, else the way most of the surface faces — a plate's faces; `axisFrom` says which) over a grid: `p5`, `p50`, `p95` (mm), and on the cells near the median (the main faces) the thickness's linear trend as `tiltDeg` — how far apart faces that should be parallel are — with `thickensToward`, its `run` from end to end and `over` what length; `faces` gives each face's own tilt off square to the axis (`topDeg`, `bottomDeg`), so a lean of the whole part shows apart from faces out of parallel. `sheet` — where over half the area has a second skin facing back along the inward normal within `reach` mm (a sample of about 6000 points, rayed as the Wall Thickness workspace does): the `gauge` (`p5`, `p50`, `p95`, mm) and `twoSkins`, that share of the area; a note calls it sheet metal when the gauge is even and 3 mm or under, and then `thickness` along the axis reads the box across the part, not the sheet. A solid part or a single skin has no `sheet`; bend radii are not read. `apart` — on such a part whose largest flat surfaces (each 2 % of the area or more) hold most of it: clusters of scan farther than `reach` mm (5 gauges, 1.5 mm at least) from every one of those walls — tabs bent in, ribs standing inside, bosses — each with `center`, `box` and `area` (mm², both skins), the largest first, six at most (`more`). A curved shell has no walls to read them off. `notes`: what looks wrong, plainly — holes, a wrap (a scanned skin with no rims at all: a wrap bridges the holes it did not see through — read each hole from both ends, `scan_heightmap` along its axis each way; `element_fit` on a bore answers `closed` where its axis runs into the skin), a noisy surface, a tessellation, a taper, a thickness that varies.

**`scan_segment`** `{ kind?: "plane", box?, minArea?, maxRms?, maxDeg?, limit?, symmetric?, mark?, list? }` — the scan's planar regions, found all at once. Read-only.
Example: `{ limit: 30, symmetric: "XZ" }`
Details: regions are grown from the flattest places outward, a vertex joining while its normal lies within `maxDeg` of the region's plane (15° by default, 60 at most) and it lies inside the region's noise band; each vertex goes to one region; a region rougher than `maxRms` off its plane (mm, 0.05 by default) or smaller than `minArea` (mm², by default a square 2 % of the scan's diagonal on a side) is given back. `box` keeps only the scan inside it. The answer gives `maxRms` and `noise` (the scan's, mm), `found` (regions in all), `shown`, `considered` and `claimed` (vertices looked at and held by regions), and the regions, the largest first, at most `limit` (20; 200 at most): each with `id` (1 is the largest), `normal` (out of the part), `point` (its centroid, on the plane), `sigma` (RMS off the plane, mm), `area` (mm²), `box`, `vertices` (a count) and `neighbours`: the regions it meets across an edge or its rounding — past the regions listed, those within 20° (a run's chain goes on through them) — each `{ id, deg, smooth }` with the angle between their normals, `smooth` when one quadric over both fits about as well as each one's own: one surface across the edge, not a crease.
A round surface does not come out as one region: a plane grows round it until its σ nears `maxRms`, so it is cut into strips that look like facets — neighbours a few degrees apart, σ near `maxRms`; that angle is the noise band's, not the part's. Such a region says `curved { sagitta }` (how far a quadric over it rises across it, mm): a strip of a curved surface, not a face. `curvedRuns`: curved regions joined across smooth edges while together they stay one surface, the largest first (at most `limit`; `runsFound` when there are more) — each `{ id, regions, area, along | cylinder { radius, axis, sigma }, note }`, `along` the direction its normals all lie square to, and the note what to model it as: an extruded profile (section square to `along`, and extrude), one cylinder (mark its regions and fit a cylinder), or freeform (section across, and sweep or loft). A region in a run says `run`, its id. Read the runs before taking regions for faces: a part whose regions are mostly curved strips is no faceted part.
`symmetric`: a plane element, or `"XY"`, `"YZ"`, `"XZ"` — each region gets `mirror { id, deg, mm }`: its twin across that plane (`"self"` when it straddles it), how far their planes differ in angle once mirrored and in place. `mark`: a region's id, or several (their points together — a run's regions), leaves its points marked — `element_fit_marked { marked: true }` fits to them; with the same options it reuses the last run, and answers `marked { points, from }` and `region` (the marked region; a list of them for several) without the list of regions unless `list: true`.

### Alignment

**`align_auto`** `{ level?: "settled" | "largest", detail?: "brief" | "full", wait? }` — a pose read off the scan: standing on its base, long side along X. `square` says how square it came out: `largest` (the largest flat face, its axis and tilt) and per axis the faces square to it with their tilts, by area — a drafted wall leans by its draft, not by the alignment. `level: "largest"` squares the largest face exactly and settles the rest about it.
Example: `{}`
Details: the pose is the directions most faces are square to and the axis round walls run along, as Auto-align then Confirm alignment do. `settled` (the default) lays all the faces on the axes at once, by area — a flange a degree off square shares its error with the base; `largest` squares the axis nearest the largest flat face exactly onto its normal and turns the other two about it onto the faces square to them. The answer gives `note` (what the pose was read from), `applied` (the transform), `elements` (how many moved, or each where it now is with `detail: "full"`) and `square`: `largest { axis, area (mm²), tiltDeg }` — tiltDeg the angle between the face's fitted plane's normal and that axis — and `axes[]`, per axis the faces square to it: `tiltDeg` weighted by area, their `area`, and `faces`, the largest three each with `area`, `tiltDeg` and `center` in the new frame. `detail` on every alignment command: `brief` (the default) answers the transform and how many elements moved with the part, `full` every element where it now is, as the list gives it.

**`align_datum`** `{ primary: { element } | { points: [3 points] } | { plane: { origin, normal } }, primaryAxis?, secondary?: { element } | { points: [2 points] }, secondaryAxis?, origin?: { element } | { point }, keepFree?, detail?, wait? }` — 3-2-1. Axes "x+", "x-" … "z-"; the primary's outward normal becomes `primaryAxis` (default z-), the secondary runs along `secondaryAxis` (default x+). An origin alone shifts without turning. Answers the transform and how many elements moved.
Example: `{ primary: { element: "Base" }, secondary: { element: "Line 1" }, origin: { element: "Cylinder 1" } }`
Details: as the panel's alignment box sets it up. `primary` levels the part — a plane, 3 points on a face that span it, or a plane given as `{ origin, normal }` (a level's `plane` from `scan_heightmap { levels: true }`) — its outward normal on `primaryAxis` (z- is the face the part stands on facing down). `secondary` turns it, square to the primary — a line or an axis, or 2 points along an edge, laid along `secondaryAxis`; or a plane, whose outward normal goes on `secondaryAxis`, not along it (a side wall as secondary with x+ ends up facing x+). `origin` is the zero point — a point, sphere or circle, or 1 point. Points are used as given, not snapped to the scan (an origin point is the zero exactly where it is; `scan_nearest` puts a point on the surface first). Each datum zeroes the coordinates it owns (a plane the one along its normal, an axis or line the two across it); the origin sets only the coordinates they leave open — with a plane and a line, the one along the line. An origin alone moves the part without turning it, all three coordinates. A primary or an origin is needed. Everything measured moves with the part. On the part's first alignment the coordinates nothing sets are centred on the scan's box centre; `keepFree: true` leaves them where they are. The answer: `applied` (the transform of this step), `appliedAlignment` (the whole alignment the part carries, when it was aligned before), `elements`, `centred` (the coordinates centred, as `["y"]`), `origin { set, at, note }` (which coordinates the origin set, where its point now stands, and a note when the datums keep it off zero — call again with the origin alone to put it at 0, 0, 0), and `parallelFace { offset, times, note }` when a face parallel to the levelling plane, from about 0.3 mm (more on a noisy plane) to 5 mm off it, holds more of the scan (its offset along the plane's outward normal, how many times the area): the part may stand on that one — level on it instead. On an embossed or warped sheet a plane fitted to the outermost faces lies on the bead crowns or the high spots, 0.3–1 mm proud of the sheet: level on the largest level's `plane` from `scan_heightmap { levels: true }`.

**`align_symmetry`** `{ detail?, wait? }` — re-poses the part on its mirror plane; refused when there is none.
Example: `{}`
Details: as Use symmetry then Confirm alignment do — the pose is Auto-align's, the mirror plane a measured symmetry plane or one searched for on the scan; the axis nearest its normal is turned onto it and the zero point put on it. Answers `note` (what it settled on), the transform and the elements.

**`align_clear`** `{ detail?, wait? }` — back to the scanner's coordinates.
Example: `{}`

### Elements

**`element_fit`** `{ kind: "plane" | "sphere" | "cylinder" | "cone" | "torus" | "point" | "circle", at: place | [place, …], rim?, side?, radius?: { min?, max? }, axis?, within?: { min, max }, mark?, sigma?: 3 | 2 | 1 | 0, knownDiameter?, assumed?, orient?: { to, relation?: "normal" | "inPlane" }, extend?, name?, wait? }` — a place is `{ point: [x, y, z] }` or `{ vertex: n }` (`{ screen }` and `{ candidate }` are not available yet). A circle goes through three or more places. `orient.to` is a plane element, a section or "XY", "YZ", "XZ". `extend` draws a cylinder (`start`, `end`) or plane (`uMin`, `uMax`, `vMin`, `vMax`) past what was measured. `knownDiameter` (sphere) holds that diameter and fits the centre alone; the fit then has `held: { freeDiameter, shift }`. Answers the element with its fit and the seed used.
Example: `{ kind: "plane", at: { point: [0, 0, 10] }, name: "Top" }`
Details, the fit: a plane, sphere, cylinder, cone or torus grows its surface from the place given, as the panel would from a click, and is best-fitted to it; a point is the place itself. `at` is one place or a list — a feature seen in patches can be seeded on each. A seed near an edge can land on the wrong surface (a cup's underside for its inside): say what is sought — `side` (`inside`: concave, normals toward the axis or centre — a bore, a cup's inside, a countersink; `outside`: convex — a shaft, a ball), `radius { min, max }` (mm), `axis` (a direction, within 20°), `within` (a box the surface stays inside) — and surfaces that do not match are passed over. A fit that finds none is refused with the radii it saw — a round turned down for its axis with that axis, a point on it, how far off it lay and its points, to give as `axis` or to drop `axis` for. `sigma` is the outlier cut-off: residuals beyond this many sigma are left out — 3 (the default the panel starts on), 2, 1, or 0 for all points.
The seeds: the answer gives the seed actually used (vertex and point), so a recipe can be replayed on another scan; with several seeds each has `inRegion` (whether the surface grew from it: one surface grows, from the seeds on it), `offMm` (how far it lies off the fitted surface along its normal, a round one's outward) and `deg` (how far its normal turns from the surface's there), and a seed left out warns where it lies: on another surface (fit each on its own, or mark both with `scan_segment { mark }` and fit the marked), or on this one outside the region it grew to (at its rim, or on a part the growing did not reach — fit it alone to see).
The region: a surface also answers `region { area (mm²), box }` and, a plane's, `normalSpreadDeg` (95 % of its normals lie within it). A plane or a cylinder warns when its points look like two surfaces, with `region.second` naming where the other lies — a plane's: its share, centroid, box, angle, offset and the σ two planes leave; a cylinder's: its share, band along the axis from the centre, axis angle, radius and how far each part's normals lean off square to the axis — shrink the box or move the seed, or fit each part with `within` (a box round its band) or `axis`. A cylinder whose region grew over two surfaces one after the other along the axis — a bore stepping wider below a flange — is parted where two cylinders fit it best and the part the seed is on answered, with `note` and `second { radius, band (mm along the axis from the centre), share }`; a refusal lists the radii it turned down and why (σ over its length, arc). A bore whose axis meets the scan at an end answers `closed { from, to, at }` (mm along the axis from the centre, where the axis meets the scan and leaves it) with a warning — a floor, or a wrap bridging a hole the scan did not see through: read it from both ends (`scan_heightmap` along the axis each way) before modelling it blind. A plane warns, with `region.fill` (the share of the rectangle it spans that it fills) and `region.sagitta` (how far a quadric over the region curves across it, mm), when it fills under 15 %, or its normals spread past 10° and the region is curved — the sagitta over three times what the quadric leaves: the crown of a bead or round, not a face — seed in the middle of the face, or give `within`. Relief on a flat face (lettering, a label) spreads the normals as wide and does not warn.
The rest: `mark: true` leaves the region's points marked for `element_fit_marked { marked: true }` (`marked` in the answer). A circle may come off an open rim of the scan instead — `rim`: its number from `scan_qa`, in place of `at`: fitted through the rim's whole loop, the answer giving `rim { index, points, rms }`; a rim that does not close on itself is refused (pick three places on it instead). `knownDiameter` (sphere only): a gauge ball, a ballbar's balls — the fit holds it and places the centre alone, which keeps the centre right on a ball scanned only partly; `fit.held` then gives the diameter the same points fit freely (`freeDiameter` — it should be close: a scan reading off moves a held centre by about as much) and how far holding it moved the centre (`shift`); refused when the surface fits a sphere more than 1 mm or 10 % off it. `assumed`: the diameter the feature was designed at, mm — a sphere, cylinder or circle is then drawn and exported at it, and still reported as measured. `orient`: align the element's direction to a reference plane, as designed — `relation: "normal"` (the default: the element's direction is the plane's normal — a parallel face, a perpendicular bore) or `"inPlane"` (it lies in the plane); the fit as measured is kept beside it and reported. `extend`: how far past the measured surface a cylinder (`start`, `end`: mm past each end, negative pulls it in) or plane (`uMin`, `uMax` along its first axis, `vMin`, `vMax` along its second) is drawn and exported; what is reported stays what was measured. `name`: otherwise it is numbered by kind — "Sphere 2".

A cylinder's answer reads its wall too, where it does not stand square: `region.taper` — `axis` (the nearest world axis where the fit lies within 10° of one, else its own), `parts` (one or two, each `band` along the axis from the fit's centre, `draftDeg`, `box`), `double` (two parts tapering the same way from a line: a double cone, widest or narrowest there) and `parting` (`at`, `radius`, `t`) — with a warning. It reads the normals between the 10th and 90th percentile along the axis, so a machined bore stays silent and rounds at the ends do not count; a wall leaning differently round the turn is left out as two cylinders at an angle.

**`element_fit_marked`** `{ kind: "plane" | "sphere" | "cylinder" | "cone" | "torus", vertices? | marked?: true | box?: { min, max }, normal?: { dir, withinDeg? }, sigma?, knownDiameter?, assumed?, orient?, extend?, name?, wait? }` — fits exactly those vertices.
Example: `{ kind: "plane", vertices: [1023, 1024, 1090, 1102, 1150], name: "Datum A" }`
Details: a surface marked by hand in the panel, with no search for the surface. `marked: true` in place of `vertices` takes the points the last `element_fit { mark: true }`, `scan_segment { mark }` or `scan_query { mark: true }` left marked; `box` every scan vertex inside it (with `normal`, only those facing a way, within `withinDeg`, 30 by default), as `scan_fit_surface` takes them — one of the three. The element keeps the marking as its recipe. With `box` the answer says how many `points` it took. The finishing fields are `element_fit`'s.

**`element_construct`** `{ kind, method, refs?, params?, seed?, vertices?, assumed?, orient?, name?, wait? }` — point: point-coords, point-centroid, point-midpoint, point-line-plane; line: line-two-points, line-axis, line-plane-plane; plane: plane-three-points, plane-offset, plane-midplane, plane-coords, plane-symmetry; circle: circle-plane-cylinder, circle-plane-sphere, circle-coords. `refs` fill the slots in order — a section, by name or id, fills a plane's slot as the plane it was cut on; `params` in order or by key (x, y, z; offset; nx, ny, nz, px, py, pz; d, cx, cy, cz). plane-symmetry takes `seed` ("XY", "YZ", "XZ", a plane or a section) and answers `symmetry: { rms, matched, sampled }`.
Example: `{ kind: "plane", method: "plane-midplane", refs: ["Left face", "Right face"], name: "Mid" }`
Details: as the panel's creation methods, from other elements and typed-in numbers (mm). A section in a plane's slot stands as the plane it was cut on (a midplane between two cuts, a line where a cut meets a face); a coordinate plane `"XY"`, `"YZ"` or `"XZ"` in a plane's slot is made a plane element through the origin first (one made so before is taken again) and listed under `made`. point-centroid and plane-symmetry measure the scan themselves: `vertices` confines them to a marked surface, `seed` starts the symmetry search from a plane. plane-symmetry finds the scan's own mirror plane as an element, the alignment left as it is (`align_symmetry` re-poses the part on it instead), and answers the search's residual, `symmetry { rms, matched, sampled }`, and a `note`. `assumed`, `orient` and `name` as `element_fit` takes them.

**`element_rename`** `{ element, name, wait? }` — dimensions keep pointing at it.
Example: `{ element: 3, name: "Datum B" }`

**`element_remove`** `{ element, wait? }` — with every construction and dimension on it.

**`element_set_visible`** `{ element? | all?: true, visible, wait? }` — a hidden element still measures.

### Sections and the 2D sheet

**`section_cut`** `{ across: element | "XY" | "YZ" | "XZ" | { axis, angleDeg }, offset?, name?, kind?: "cut" | "shadow", play?, tolerance?, smoothDeg?, extrude?, wait? }` — keeps a section; a coordinate plane goes through the part's centre unless `offset` gives the coordinate; a shadow takes no `offset`, it is drawn in the middle of the part. Answers its plane and chain count; a shadow also its `play`, `tolerance`, `smoothDeg`, `loops` (hole, pieces), `areaMm2`, `outside` { min, max } and `extent` along the normal.
Example: `{ across: "XY", offset: 6.5, name: "Mid height" }`
Details: the section is measured in the 2D workspace (flat), where it is put on the sheet. `across` is an element with a direction (a plane, cylinder, cone, line or circle) by id or name, or a coordinate plane (`"ZX"` is taken too). `{ axis, angleDeg }` is a plane through an axis — a cylinder's, cone's, line's or circle's by id or name, or the coordinate axis `"X"`, `"Y"` or `"Z"` through the origin — turned `angleDeg` about it: a half section of a turned part, u the distance out from the axis and v up it (towards the + end of the coordinate axis it lies nearest, whichever way the element points), normal u × v, at every angle; 0° is the coordinate axis next round (X about Z, Y about X, Z about Y) and the angle turns by the right hand about the axis — about Z, from +X towards +Y; `offset` is 0 by default there. `offset` slides the plane along its normal, mm, from the element. A shadow (`kind: "shadow"`) is the whole part projected along the plane's normal onto the plane, its outer boundary as closed loops (holes marked) — the widest outline, every indentation filled, for a bin, a foam cutout or a pocket — read as lines and arcs to `tolerance` (mm, 0.1 by default) and lying between `play` and `play + 2·tolerance` outside the part's exact silhouette (`play` in mm, 1 by default; 0 for none, negative is a press fit); where two lines meet turning by less than `smoothDeg` (30° by default, 0 for none) the corner is rounded by an arc tangent to both, sharper ones kept. The loops are drawn in the middle of the part's thickness along the normal. `extrude` (true by default; false keeps it flat) stands it up as a block through the part's thickness along the normal (the part's lowest point to its highest), drawn in 3D and written by `export_step` as a solid in the solids form, a planar face per end and a face per line or arc. `name`: otherwise numbered — "Section 2".

**`section_get`** `{ section, chains?, space?: "sheet" | "world" | "both", limit?, skin?: "outer" | "inner", facing?: { dir: [u, v], withinDeg? } }` — each chain's points in order ([u, v] mm on the section plane; [x, y, z] with world), closed or not, length, box, and the plane (origin, normal, basisU, basisV: a sheet point is origin + u·basisU + v·basisV). 4000 points by default, 50000 at most.
Example: `{ section: "Mid height", limit: 2000 }`
Details: [u, v] are what `flat_fit` and a sketch on the section take; `world` is the frame the part is measured in now. A closed chain is a loop, its first point repeated at the end; `length` runs along the path, `points` counts them, `bounds` is the box on the sheet. Past `limit` every k-th point of a chain is kept, its ends always, and `step` says k; `kept` counts them. `chains` picks chains by index. `skin` reads one skin of a thin wall alone — `outer`: the points whose way out of the material (the scan's triangles say which way that is) faces away from the middle of the cut and looks out past the rest of it; `inner`: the points facing the middle whose way back through the material comes out on the outer skin within about the wall's thickness; ribs and bosses are neither, and a solid has no inner skin. `facing` keeps the points whose way out lies within `withinDeg` (45 by default) of a direction on the sheet; with both, a point must pass both. Each chain then comes back as its runs on that side, each with `run` (its place along the chain) and four points at least.

**`section_render`** `{ section? | plane?, offsets?, up?: "x" | "y" | "z", frame?: { at, size } | { world: { min, max } }, tolerance?, layers?, width?, height?, path? }` — a PNG of a section, for checking a slice against what was built on it. Read-only; needs the browser.
Example: `{ section: "Mid height", frame: { at: [20, 8], size: 30 } }`
Details, the picture: the scan's cut as points on the section's sheet ([u, v] mm as `section_get` gives them, +u right, +v up), a grid ruled in millimetres with its values at the top and left margins — world coordinates where the sheet's u or v runs along a world axis, sheet mm otherwise — the world direction across and up named in the margins (`axes` in the answer: per sheet axis the world axis it runs nearest, `offDeg` and, along it, `at0`, the world coordinate at the sheet's 0), a scale bar, and over it what the workspaces' layers draw — a model's cut by the section's plane as outlines, a sketch's pieces with their ids where the sketch lies in that plane, whatever it was drawn on. Every scan point within ten tolerances of an outline is read against it: on it within ± `tolerance` (grey), or off it (red), outside the outline or inside it; points with no outline near are pale. The answer gives `gap`: `points` (the cut's), `read`, `over` (red), `outside` and `inside` (of a closed outline — inside is scan within the model's material, so the model stands proud there; outside, the model is short), `max` and `rms` (mm) and `overBox` (the sheet box round the red, to frame the next look); `layers`: each layer drawn by key, its outlines and pieces counted; `map`: picture pixel (column c, row r from the top) is the sheet place `[left + c·unitsPerPx, top − r·unitsPerPx]`; and `sheet` — the sheet in the world every time: `origin`, `normal`, `basisU`, `basisV` (a sheet point [u, v] is `origin + u·basisU + v·basisV`). `tolerance` is the Deviation workspace's by default; `layers` names the keys to draw, every one by default, `[]` for the scan alone (an unknown key is refused with the keys there are). 800 px on the long side by default, up to 2048.
The plane: `section` names a section; or `plane` cuts the scan for the picture alone — no section is made, and the sheet is a sketch's on that plane: zero at the world origin's foot, u along the coordinate axis next round from the normal (YZ: u = Y, v = Z; XZ: u = Z, v = X; XY: u = X, v = Y), so on a coordinate plane [u, v] are world coordinates (the answer's `sheet` gives them). `plane` is `{ origin, normal }`, a coordinate plane `"XY"`, `"YZ"` or `"XZ"` (also `"ZX"`; through the part's centre, as `section_cut` lays it — the answer's `sheet` gives its origin), an element by id or name (the plane through its centre square to its direction — a plane element's normal, a cylinder's axis — on the sheet a sketch on it takes, not the fitter's own axes), or `{ sketch }` by id or name: the scan cut on that sketch's plane, in its own frame, so [u, v] are its pieces'. A section's own sheet counts from the part's centre instead (across an element or through its axis, from the element's centre).
`up`: `"x"`, `"y"` or `"z"` turns the picture's sheet in its plane so that world axis runs up it — a side view with Z up: v is that axis laid into the plane, u the direction square to it running + to the right, the plane seen from whichever side gives that (the XZ plane with up "z": u = X, v = Z, seen from −Y, as a front view; a section's sheet keeps its zero) — and everything the picture says in [u, v] (`frame`, `map`, `overBox`, `axes`) is then on that turned sheet, which the answer gives as `sheet`. An axis along the plane's normal is refused.
`offsets`: 2 to 9 cuts in one picture — the section's or plane's slid along its normal by each, mm (a coordinate plane by name counts from the world's zero here, so `"XY"` with `[0, 5]` cuts at Z 0 and Z 5; alone it lies through the part's centre) — side by side, each tile labelled with its offset, all on one frame and scale (the square round every cut unless `frame` is given); the answer gives per tile its `offset`, `origin` and `gap` (and `layers` where any drew), and `map.tile` and `map.cols` (`map` holds for each tile from its own corner); 1200 px across by default.
`frame { at, size }` looks at a square of the sheet — `at` as [u, v] on the sheet, or as [x, y, z] in the world, laid square onto the sheet, so a place on the part needs no working out of where the sheet counts from (`framed` gives where it came out on the sheet, and `offPlane` how far off the plane the point lay, mm) — or `frame { world: { min, max } }` at the square round a box of the world laid onto the sheet, a tenth wider; everything by default.

**`flat_open_image`** `{ path, name?, wait? }` — a PNG or JPEG flatbed scan on the sheet. Not undoable.
Example: `{ path: "C:/scans/gasket.png" }`
Details: at the highest optical resolution, in place of the image there was. The scale it declares about itself is taken until it is calibrated. Needs the browser; a new image starts a new history.

**`flat_calibrate`** `{ mode: "distance" | "diameter", points: [[x, y], …], mm, wait? }` — two places a known distance apart, or three or more on a circle of known diameter.
Example: `{ mode: "distance", points: [[10.2, 5.1], [110.4, 5.3]], mm: 100 }`

**`flat_detect_edges`** `{ sensitivity?: 0–1, wait? }` — finds the edges again; chain numbers change.
Example: `{ sensitivity: 0.6 }`
Details: 0 keeps only the strongest edges, 1 every faint one — what the edge methods of `flat_fit` and the snapping of every place follow. Needs the browser; answers how many chains were found.

**`flat_edges`** `{ box?, near?, reach?, minLength?, tolerance?, limit? }` — edge chains by number, longest first or nearest a place; `tolerance` adds thinned polylines. Read-only.
Example: `{ near: [42, 18], reach: 3, limit: 5 }`
Details: what `flat_fit` takes as `chains` and `flat_render` writes beside each. Each with its `length`, whether it `closed` on itself, how many `points` and the `box` round it, in the sheet's units; with `near` each has `nearest { at, distance }`, and `reach` keeps only the chains that close. `box` keeps the chains that enter it, `minLength` the long ones. The polylines are thinned to stray no further than `tolerance`, 5000 points at most over all (`polylinesLeftOut` counts the rest). `limit` 50 by default, 2000 at most. The numbers hold until the edges are found again.

**`flat_objects`** `{ threshold?, dark?, minArea?, outline?, limit? }` — parts on an image: area, holes, box, centroid, equivalent diameter, Feret widths, axis angle, chains. Read-only.
Example: `{ minArea: 5 }`
Details: the parts are parted from the background by a grey level (Otsu's, unless `threshold` 0–255 is given; `dark` says the parts are darker than the background, read off the image's border by default) and numbered in reading order — rows from the top, left to right. `area` leaves the holes out; `equivalentDiameter` is of a circle of its area; `feret` gives the largest and smallest caliper widths (`max`, `min`) and the directions they are measured along (`maxAngle`, `minAngle`, degrees from +X); `axisAngle` its long axis; `chains` the edge chains along its outline, longest first, six at most. `minArea` drops smaller ones: 1 mm² by default, or its pixels at 600 dpi on an image with no scale. `outline` adds each outline as a polygon thinned to that tolerance. `limit` 100 by default. A section's outlines are its edge chains (`flat_edges`), not objects.

**`flat_fit`** `{ kind: "point" | "line" | "circle" | "arc" | "spline", method?, points?, chains?, box?, refs?, name?, snap?, reach?, wait? }` — methods: flat-point-pick, flat-point-midpoint, flat-point-intersect, flat-point-center; flat-line-pick, flat-line-seed, flat-line-edge; flat-circle-pick, flat-circle-seed, flat-circle-edge; flat-arc-pick, flat-arc-edge; flat-spline-pick.
Example: `{ kind: "circle", method: "flat-circle-edge", points: [[42.1, 18.3]] }`
Details: as the sheet's tools; the kind's first pick method is the default. A pick method takes `points`, the places clicked — each snapped to the nearest detected edge within `reach` unless `snap: false` (true by default, as the panel's Snap box is; `reach` is ten image pixels by default, in the sheet's units), and the answer's `picks` say where each landed (`at`), on which `chain` and how far it `moved`. A seed method takes one place on a detected edge and grows along it; an edge method a place on an edge, taken whole — a place with no edge within reach is refused naming the nearest chain and where. The edge methods also take `chains` — whole edge chains by number (`flat_edges`, `flat_render`) — and `box`, every edge point inside it (of those chains only, with both); the kind's edge method is the default then. A construct method (midpoint, intersect, center) takes `refs`, other 2D elements by id or name.

**`flat_dimension_add`** `{ refs: [2 elements], type?: "flat-dist-point-point" | "flat-dist-point-line" | "flat-dist-line-line" | "flat-angle-line-line", name?, wait? }`
Example: `{ refs: ["Circle 1", "Circle 2"] }`
Details: points, circles and arcs count as their point (centre), lines as lines; without `type`, the first that takes the two elements in the order given. Answers the dimensions on the sheet and the report.

**`flat_set_alignment`** `{ origin?: [x, y], xAxis?: [x, y], clear?, wait? }`
Example: `{ origin: [42.1, 18.3], xAxis: [90.0, 18.3] }`
Details: the part's zero point at `origin` and its X axis through `xAxis`, as the Align tool's two clicks do (each snapping to an edge as a click does): the report, the panel and the exports then read in that frame. Places given to the commands stay the sheet's own. `clear: true` takes the alignment off.

**`flat_profile`** `{ object? | chains?, about?, axis?: "radial" | "axial", samples?, prominence?, mark?, points? }` — peaks of an outline: count, pitch, envelope.
Example: `{ object: 1, axis: "radial", mark: true }`
Details: the teeth of a knurl or a gear. The outline is an object of the last `flat_objects` by number (on this image, at this scale), or edge chains by number (several make one). `radial` (the default) reads the radius against the angle about `about` — a circle, arc or point — or about the outline's own centre: a part standing upright, seen from above. `axial` reads the distance from `about` — a line — or from the outline's own long axis, against the position along it, each side apart (left and right of the axis's direction): a part lying on its side. A peak counts when it stands `prominence` above the higher of the valleys either side — by default 0.3 of the profile's spread, never under the outline's noise (a pixel and a half of an image, a hundredth of a millimetre of a section). `samples` are the bins round the turn or along the axis, 16 to 20000, from the point count by default. The answer gives per side the `count`, the `pitch` (degrees round, or along the axis), the `envelope` (`max`, `min`, `peakMean`, `valleyMean`; radial also as `diameter`) and every peak's angle or position and place (`peaks`); `points` adds the sampled profile (720 at most). `mark: true` puts a count on the sheet with a numbered pick on every peak, to check by eye — one undo step; otherwise nothing changes.

**`flat_note_add`** `{ text, at: [x, y], wait? }`; **`flat_edit`** `{ element? | dimension? | note? | count?, name?, text?, at?, visible?, wait? }`; **`flat_remove`** `{ elements?, dimensions?, notes?, counts?, wait? }`
Example: `{ text: "Gasket A, 2 mm cork", at: [5, 5] }`
Details: a note is one line, as the Text tool writes it — a line break is written as " / " — and `at` is its lower-left corner in the sheet's units; it is drawn on the stage and in `flat_render`, written into the SVG and DXF exports and listed in the report. `flat_edit` changes one thing named by id (or name; a note by id): an element, a dimension or a count takes a new `name`, a note new `text` or a new place; `visible: false` leaves it out of the stage, the picture and the exports, true brings it back; an element that cannot be fitted any more cannot be renamed — remove it. `flat_remove` takes them all or none (a typo removes nothing): an element built on a removed one stays and says it has lost its source (`unfit`), and a dimension on one turns invalid (`invalidDimensions`), as in the panel; the answer lists `removed` and what is left.

**`flat_render`** `{ frame?: { min, max } | { at, size }, width?, height?, show?: { image?, edges?, chains?, elements?, dimensions?, notes?, labels?, grid? }, path? }` — a PNG of the sheet, +X right, +Y up, with a grid; `map` turns pixel (c, r) into [left + c·unitsPerPx, top − r·unitsPerPx].
Example: `{ show: { chains: true }, frame: { at: [42, 18], size: 30 } }`
Details: drawn as the sheet lies in its own units, whatever the stage's alignment or turns, the grid's values along the top and left edges (`grid` in the answer gives the step; `unit` says mm or px). `frame` zooms in on a box; `size` may be `[width, height]`. `show` layers: `image`; `edges` (the detected chains — as the panel shows them by default); `chains` (their numbers, as `flat_fit` and `flat_edges` name them); `elements` (with counts and the alignment); `dimensions`; `notes`; `labels` (names and readings); `grid`. The picture is the frame's shape, 800 px on the long side by default, up to 2048.

**`flat_report`** `{}` — the 2D report as the panel's Copy gives it.
Example: `{}`
Details: the image or section, the scale it rests on, the alignment, every element, dimension, count and note.

### Deviation

**`deviation_open_reference`** `{ path, name?, units?, wait? }` — STEP, STL, PLY, OBJ or 3MF as the reference; any alignment against the old one goes. Not undoable.
Example: `{ path: "C:/parts/bracket.step" }`
Details: the nominal part the scan is compared with, STEP straight from CAD; the map against the old one goes with the alignment, the elements measured on the scan stay. `units` as `scan_open` takes them. Answers the deviation state; a new reference starts a new history.

**`deviation_align`** `{ mode?: "auto" | "points" | "local", pairs?: [{ scan, reference }, …], vertices?, searchDistance?, wait? }` — rigid best fit, no scale; answers RMS, points matched, transform and the map's statistics.
Example: `{ mode: "local", vertices: [1023, 1024, 1090, 1102], searchDistance: 0.5 }`
Details: the deviation map is measured under the fit. `auto` (the default) finds the pose on its own; `points` starts from three or more pairs of corresponding points — a point on the scan and the same point on the reference, mm — then refines; `local` refines the fit in hand on a marked surface only (`vertices`, scan vertex numbers), within `searchDistance` mm — it needs an alignment to refine.

**`deviation_settings`** `{ range?, maxDistance?, bands?, tolerance?, facingDeg?, colormap?: "jet" | "viridis" | "magma" | "plasma" | "inferno" | "cividis" | "mako" | "rocket" | "turbo", on?: "scan" | "reference", show?, wait? }` — answers the deviation state with `settings.colormap` (the ramp at −range, 0, +range, the caps, the unmeasured grey) and `settings.show`, the map switch: `show: false` leaves the surface bare, the map still measured; a project keeps it.
Example: `{ tolerance: 0.1, range: 0.3, maxDistance: 1.5 }`
Details: `range` is the colour scale, ± mm; `maxDistance` how far from the reference a point may be to count, mm (given by hand it is no longer automatic); `bands` a stepped scale of that many colours (2 or more) or null for smooth; `tolerance` ± mm, the share within which the statistics give; `facingDeg` how far the reference surface a point is measured against may turn from facing it, 1–90°, or null for the nearest surface whatever it faces — a change of it measures the map again. `colormap` is the colour map every deviation map is drawn in — the person's own choice, kept in the browser and outside the undo, so set it only to read a render by its colours, and read `settings.colormap` for what the ramp shows at −range, 0 and +range and the caps past either end before judging a picture; jet is blue inside, green on the surface, red outside, the rest perceptual ramps. `on` is which surface a map against the reference part is painted on: `scan` (the scan by its distance to the reference, the default) or `reference` (the reference by its distance to the scan, measured the first time it is asked for: positive where the reference stands outside the scan — material the part has not, a boss or a wall the model has and the scan does not — negative where it is short of it, grey where no scan stands behind it, a reading past the search distance in the cap of its end; refused while the map is against an element). Read both: the scan's side finds what the model lacks, the reference's what the model has that the part has not, and how much of the model no scan supports (`onReference.noScanPct` in the state). `show` is the view bar's Map key: false leaves the surface bare to look at its shape, the map still measured and read — the figures, hotspots and pins go on; true paints it again; read `settings.show` in the state when a render comes out uncoloured. The map paints in the Deviation workspace only — a command of another workspace puts that one on screen, and `workspace_set deviation` brings the map back; `view_render` pictures the side on screen there and says which map it painted (`map`) or why none (`mapWhy`), elsewhere that the Deviation workspace is not on screen.

**`deviation_measure`** `{ wait? }` — measures the map again under the alignment in hand.
Example: `{}`
Details: after a change of facing limit or search distance, say; `deviation_align` measures it already. Answers the map's statistics: min, max, mean, RMS, sigma, share within the tolerance, points matched.

**`deviation_hotspots`** `{ tolerance?, patches?, grain?, on?: "scan" | "reference" }` — patches over tolerance (centre, box, area, vertices, mean, extreme, side, a few vertex numbers), `found`, `over`, and `far: { inside, outside, count }`, `unmeasured`. Read-only.
Example: `{ patches: 12 }`
Details: the scan vertices whose deviation lies past the tolerance (the map's own, under `deviation_settings`, unless `tolerance` says otherwise) gathered into connected regions, the largest and farthest first — where the part is off, how large each place is and by how much, instead of one number over the whole part. Each patch: `centroid` and `box` in mm (in the frame the scan is measured in — what `scan_query { box }` and `element_fit` take), `area`, `count` (vertices), `mean` and `extreme` deviation, `depth` (the median |deviation| over the patch), `volume` (mm³ past the tolerance, the ranking key), `kind` — `feature` when the patch is at least 4 mm² and 25 point spacings² across and its depth at least 2× the tolerance: material missing or misplaced, to model or to name; else `texture`, the surface's own roughness poking past the tolerance, small or shallow — `side` (outside the reference or inside), `at` and `vertex` (the point of the extreme and the scan vertex there), `vertices` (a few of its own, what `element_fit_marked` takes), and with a map against the reference part `onReference { centroid, at }` — what the Deviation workspace shows and `view_render { frame }` takes there. `grain` is how close two vertices over tolerance have to be to be one patch, three point `spacing`s by default. `features` says how many of all the patches found are features and their share of everything past the tolerance (`shareOfExcess`, 0–1), with what a feature patch asks: a patch over a tolerance well above the scan's noise is never noise, so read each by its kind — a feature is modelled or named, never put down to scatter. `found` and `over` say how many patches and vertices over tolerance there were in all — within the search distance, the vertices the map draws as a measurement. `far` is the vertices past the search distance, which the map draws bare: `far.inside` is the scan deeper inside the reference than the search distance, where the reference has material the part has not (a hole, a pocket or a slot the model lacks); `far.outside` the scan further off it, where the part has what the model has not, or scan spray; each with its `count`, `found` and `patches`, the largest first, and `far.count` both together. `unmeasured` says how many vertices the facing limit left without a reading. `patches` 8 by default, 50 at most. `on: "reference"` reads the map on the reference instead (`deviation_settings { on }`, measured if it is not yet): the patches are of the reference, in its frame, `outside` where the reference stands proud of the scan (material the part has not) and `inside` where it is short of it; `far` is the reference past the search distance from the scan, by side; and `noScan`, the reference with no scan behind it, in patches the largest first — surface the model has on no evidence: inferred, unscanned, or not on the part.

**`deviation_volume`** `{ tolerance?, cell?, regions?, within?: { min, max }, kinds?: ["excess" | "missing" | "unsure"], wait? }` — the volume error: totals (mm³ and % of the reference), `cell`, `smallestSeen`, `found`, and the largest regions (8 by default): `kind`, `volume`, `maxDepth`, `thickness`, `shape`, `centroid`, `deepest`, `box`, `evidence`, `confidence`. Needs `deviation_align`; about 15 s on a 1.5M-triangle scan, less `within` a box. Read-only.
Example: `{ regions: 12, kinds: ["excess", "missing"] }`
Details: the scan and the reference compared as solids on a grid of small cells — each cell inside one and not the other is an error, touching cells a region. `excess` is material the reference has and the part has not (a boss modelled where there is air, a hole not cut), `missing` material the part has and the reference has not (a boss not modelled, a pocket cut where the part is solid), wherever it is: behind a wall, inside a cavity, past the search distance. Where the scan has a hole the reference stands in for it; what the scan still does not say is `unsure`, never an error. Within the tolerance of the scan's surface a difference is noise; nothing thinner than `smallestSeen` (two cells) is seen. Each region: `volume` (mm³), `maxDepth` (mm from the scan's surface), `thickness` (volume over the area it shares with a surface), `shape` — `layer` (a face standing off, about `thickness` thick) or `lump` (material there or not) — `centroid`, `deepest` point and `box` in the reference's frame (what `view_render { frame }` takes in the Deviation workspace), `evidence` (the share of its scan side that is real scan rather than reference standing in) and `confidence`. `tolerance` is the map's by default; `cell` by default half the tolerance or a 250th of the reference's longest side, the larger — and coarser if the grid would pass 16M cells; `regions` 50 at most; `within` is a box in the reference's frame; `kinds` names only those kinds, the totals being of all. The regions are shown in the Deviation workspace, the colour plot put away; nothing kept changes.

**`deviation_set_target`** `{ element: element | null, side?: "outward" | "inward", facingDeg?, wait? }` — the map against one fitted element; null goes back to the reference.
Example: `{ element: "Datum A" }`
Details: a plane, cylinder, cone, sphere or torus, as choosing the element in the panel does. `side` is the material side, read off the scan when the element is chosen (`outward`: the element's outer side; `inward`: a bore or shell) — give it to override. `facingDeg` limits which surface counts to what faces the element within that many degrees (1–90), null for any. Needs the viewport; answers the map's statistics.

**`deviation_export`** `{ side?: "scan" | "reference", format?: "ply" | "npy" | "csv", path? }` — the deviation map as a file of readings, for working on it elsewhere. Read-only.
Example: `{ format: "csv", path: "C:/scans/out/deviation.csv" }`
Details: `side: "scan"` (the default) writes a reading per scan vertex — its place in the frame the scan is measured in (what `scan_query` gives) and its signed distance from the reference part, or from the element `deviation_set_target` measures against; `side: "reference"` a reading per sample of the map on the reference (`deviation_settings { on: "reference" }` — measured if it is not yet), in the reference's frame, positive where the reference stands outside the scan. `ply` (the default) is binary: float x, y, z, deviation and uchar measured; `npy` an N × 4 float32 array x, y, z, d, for numpy.load; `csv` x,y,z,d for a spreadsheet. The distance is NaN ("nan" in the CSV) where there is no reading; a reading past the search distance is kept as it is — the map draws it bare and the statistics leave it out, so `measured` is 0 on it (PLY), and in the others |d| ≤ searchDistance says it counts. The answer gives the file and the figures to check it by: `readings`, `measured`, `withinTolerance` and `withinTolerancePct` (of the measured, ± tolerance — on the scan's side what the deviation state's stats give; on the reference's, by reading, where the state gives it by area), `tolerance` and `searchDistance`.

The reading: `low` and `high` are the ends of the colour scale, mm; `bands` a stepped scale (2 or more) or null for smooth; `limit` the thin-wall limit the statistics count under, mm. Answers the thickness state.

**`thickness_measure`** `{ method?, maxThickness?, coneRays?, coneAngleDeg?, normalDeviationDeg?, wait? }` — min, max, mean, sigma, share under the limit, points measured.

### Pictures

**`view_render`** `{ view?: "iso" | "iso-front-left" | "iso-rear-left" | "iso-rear-right" | "top" | "bottom" | "front" | "rear" | "left" | "right", views?, fit?, frame?: { min, max } | { at, size }, show?: { scan?, reference?, sections?, elements?, labels? }, section?: true | false | { across, offset?, flip? }, width?, height?, path? }` — a PNG of the viewport, 800 px on the long side by default, up to 2048; waits for the session to settle. In the Deviation workspace the answer says what is painted: `map: { on, colormap, range }`, or `map: null` and `mapWhy` (switch off, no map, the surface it is on put away — and what puts it there); `mapNote` when the reference ghost over the scan dulls the colours — `show: { reference: false }` for the clean map.
Example: `{ view: "iso", width: 1400, path: "C:/scans/out/iso.png" }`
Details, the picture: what the person sees in the viewport, without the HTML labels over it (dimension values, names), lit from a little above and left of the camera with more fill than the screen, so a face square to the camera keeps its shading. `width` and `height` in pixels (64 to 2048): the viewport's own shape at most 800 px on its long side by default, enough to check a step by — ask for more for a picture to keep; one of them alone keeps the viewport's shape. The views: `iso` is from the front, right and above; `iso-front-left`, `iso-rear-left` and `iso-rear-right` the other corners, as high up; `top` down the Z axis, Y up the screen; `front` from −Y, Z up; `rear` from +Y; `left` from −X; `right` from +X — the camera turned about the middle of the screen. `views`: two to six standard views in one picture, side by side, each fitted and named in its corner — iso, top, bottom and a side as one picture to look at instead of four (`width` and `height` are then the whole sheet's; 1200 px across by default); the view stays at the last; not with `view` or `frame`.
Framing: `fit: true` brings everything shown into the frame, keeping the direction looked from; a view alone turns and keeps the zoom, and a `frame` stays for the pictures after it — the answer says `fitted`, and `framedEarlier: { box | at, size, note }` while the camera still stands on an earlier frame (`fit: true` pictures it whole). `frame { min, max }` is a box in the frame the part is measured in now, framed whole as seen from the view's direction; `frame { at, size }` a place in the middle of the view, `size` the side of a square fitted in the picture's shorter side, in any view, the iso too: 40 in an 800 × 450 picture is 40 tall and 71 wide — `mmAcross: [width, height]` in the answer says what the picture spans, mm. A corner or a fillet looked at closely; the direction looked from stays, and fit is left alone.
`show` puts the scan, the reference (the Deviation workspace's reference part), the sections, the elements (the measured elements and dimensions), the labels (the name tags and readouts over the part) — or what a workspace adds — on screen or away for the picture alone, by key, and back as they were after it; `{ scan: false }` pictures what was built on the scan on its own; `view_set` lists the keys. `false` on a workspace's key not on screen now does nothing and is answered under `absent`. A workspace's key that is off in the picture, and not put away by `show`, may say why and what shows it under `<key>Why`. `section` cuts everything open for the picture alone, as `view_set` does.
The map: in the Deviation workspace the answer says which map the picture shows — `map: { on: "scan" | "reference", colormap, range }` — or `map: null` and `mapWhy`, why none is painted (the map switch off, no map measured, the surface it is on put away, the view split) and what puts it there. With the scan shown, a reference shown with it is drawn over it as a ghost and dulls the colours (`mapNote` says so). In another workspace, with a deviation map measured, `map: null` and `mapWhy` say it paints in the Deviation workspace alone (`workspace_set deviation`); a workspace that colours the part its own way answers `map` or `mapWhy` for its own. The picture waits for the session to settle first — a map being measured, on the scan or on the reference, too. Pictures and `view_set` take the viewport one at a time: two asked for together come back as two, one after the other. While the 2D workspace is on screen the 3D view is not drawn: `flat_render`, or `workspace_set measure`.

**`view_set`** `{ view?, fit?, frame?, show?, section? }` — the same, kept; answers every show key standing now. Not an undo step.
Example: `{ view: "top", fit: true }`
Details: with neither `view` nor `fit` it fits; the zoom a frame leaves stays for what comes after it, a standard view without `fit` included. `show` leaves the keys as set — `{ scan: false }` to look at what was built on the scan without it. `section` opens the section view and leaves it so: `true` opens it as the Section key does — square to the view, through the part's middle; `false` puts it away; `{ across, offset?, flip? }` lays it across a coordinate plane `"XY"`, `"YZ"`, `"XZ"` or an element with a direction, `offset` along its normal (mm: for a coordinate plane the coordinate, for an element from its centre), `flip` taking away the half away from the camera instead — everything cut open at the plane, the half toward the camera taken away, closed parts capped, to see inside; set after any turn. It waits for the session to settle first (a fit, a map, a rebuild), so what was just made is in the frame. The answer: `view`, `fitted`, `framed` (the frame asked), `framedEarlier`, `size`, `mmAcross`, `section` (`across`, `offset`, `takenAway`, `tilt`, `cutsNothing`; null when off), `shown` (every key that can be shown now and whether it is) and `<key>Why` for a workspace's key that is off and not put away by `show`.

## Errors

A refusal is `code: message`.

| Code / message pattern | Cause | Fix |
|---|---|---|
| **unknown_command** "There is no tool …" | The tool is not on the page (stale list, older build) | `scanruler_status`; load the tools again |
| **invalid_input** | The input does not fit the schema, or names something that cannot be used there | Read the message; it names the field |
| **invalid_input** "Could not read …: there is no such file" | A `path` that does not exist on the server's computer | Absolute path, or relative to the agent's folder |
| **invalid_input** "… has no direction to cut across" | `section_cut` across a point or sphere | Cut across a plane, cylinder, cone, line, circle or a coordinate plane |
| **invalid_input** "Give box or near — one of them." | `scan_query` with both or neither | One of them |
| **invalid_input** "show.…: no such key" | A show key not on screen in this workspace | Use the keys `view_set` lists |
| **invalid_input** "… is the server's own and is not batched" | A server tool inside `scanruler_batch` | Call it on its own |
| **busy** "The session is busy — …" | Loading, fitting or measuring already, or the person is | `scanruler_wait { for: "idle" }`, then retry |
| **no_scan** "No scan is open" | A scan tool with no scan | `scan_open` |
| **not_found** | An element, dimension, section, chain, checkpoint or job named does not exist | Read the list the message gives; 2D chain numbers change after edge detection |
| **invalid_state** "The 3D Measure panel has … — finish or cancel it there first" | The person has something open in the panel | Ask them to finish or cancel it |
| **invalid_state** "The session holds <what> [in the project "…"] … that … would replace" | `scan_open`, `project_load` or `session_reset` over work | `saveTo` on the same call (the session saved there first), `project_save` first, or `discard: true` |
| **invalid_state** "The 2D workspace is on screen …" | `view_render` while the sheet is shown | `flat_render`, or `workspace_set { workspace: "measure" }` |
| **invalid_state** "Nothing is on the 2D sheet" | A flat tool with no image or section | `flat_open_image`, or `section_cut` |
| **invalid_state** "No edges are detected on the sheet" | Edge methods with no edges | `flat_detect_edges` at a higher sensitivity |
| **invalid_state** "There is nothing to undo" | Empty history | — |
| **invalid_state** "The history no longer holds the step the checkpoint was made on" | `history_restore` after the mark was undone or the history restarted | Nothing was undone; read the state |
| **failed** | Ran and did not succeed: a fit that found no surface, a file that would not read | Read the message; move the seed or change the input |
| **failed** "The plane misses the scan" | `section_cut` offset outside the part | A coordinate within the bounding box |
| **failed** "The scan casts no shadow on that plane" | `kind: "shadow"` on a plane the scan is seen edge-on from (a sheet) | Another plane, or a cut |
| **failed** "Gave up waiting for … after N s" | The app did not settle in time | `scanruler_wait { for: "idle" }`, read the state before retrying |
| **unavailable** "… needs the ScanRuler page" | A headless server: no scan, viewport or browser | Start scanruler-mcp in page mode, paired with a tab |
| **unavailable** "No ScanRuler page is connected" | No tab paired | `scanruler_open` |
| **unavailable** "The mesh worker is not running" | The page is still starting | `scanruler_wait { for: "idle" }` |
| **not_implemented** | `{ screen }` or `{ candidate }` places | Use `{ point }` or `{ vertex }` |
| **internal** | A fault of the app | Report it with the call; try another route |
